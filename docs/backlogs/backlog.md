## ⬜ 서버 골격

### S1. Node/TS 프로젝트 셋업 `[서버][소]`
- TS + WebSocket(`ws`) + 빌드/실행 스크립트. `data/world` 로더(번들 `rooms.json` → 메모리 객체 그래프).
- 방↔출구 양방향 인덱스, 오브젝트/몬스터 템플릿 맵.

### S2. 월드 인메모리 모델 `[서버][중]`
- 원본 `Rom[]`/linked list에 대응하는 in-memory 표현: 방 인스턴스(현재 플레이어/몬스터/아이템 라이브 리스트), 템플릿→인스턴스 생성.
- `broadcast_rom`/`broadcast` → 방 단위 `EventEmitter` 채널로 대체.

### S3. 접속/세션 + 명령 파서 `[서버][중]`
- WebSocket 연결 = 플레이어 세션. 원본 `process_cmd`/`parse`/`cut_command`(io.c, command*.c) 로직 참고해 명령 디스패치 골격.
- 한글 명령어/방향(북남동서/위밑/numpad) 매핑(`han.c` `get_exit_char` 참고).

### S4. 구조화 이벤트 프로토콜 `[서버][설계][중]`
- 서버→클라 메시지 스키마 정의: `room`(설명+출구+가시 오브젝트/몬스터), `stats`(hp/mp/...), `inventory`, `message`(채팅/전투로그), `combat` 등.
- 텍스트 대신 구조화 JSON을 내보내는 것이 사용성 개선의 전제(웹 UI가 여기에 의존).

### S5. 핵심 게임플레이 이식 (점진) `[서버][대]`
- 이동, look, 인벤토리/장비(wear/ready), 줍기/버리기, say/채팅.
- 전투(`creature.c`/`comman5_old.c` `attack`), 마법(`magic*.c` `cast`), 은행(`bank.c`) — 검증된 필드 오프셋으로 스탯 그대로 이식. 필요 시 원본을 oracle로 대조.
- 💭 전투 공식/주사위/thaco 룰은 원본 코드를 정확히 재현(밸런스 유지).

### S6. 영속화 (MongoDB) `[서버][중]`
- 월드 정의·플레이어 세이브·게시판을 Mongo로. 부팅 시 월드 로드, 플레이어는 로그아웃/주기 저장.
- 💭 Redis(pub/sub broadcast, 세션)는 멀티프로세스/내구성 필요 시점에 도입.

## ⬜ 웹 UI / 사용성

### U1. 웹 클라이언트 기본 `[UI][중]`
- WebSocket 연결 + 메시지 로그 + 입력창. Tier 1: **나침반/클릭 출구 패널**(방향 + 이름 출구 버튼).
- HP/MP 바, 인벤토리/장비 패널, 채팅 채널 탭 분리.

### U2. 자동지도(automap) `[UI][대]`
- 시작 방에서 BFS, 방향 출구(북→y+1, 동→x+1, 위→z+1…)로 `(x,y,z)` 좌표 부여 → 층별 2D 타일 격자 + fog-of-war.
- 존(`r00~r10` = `id/1000`)별 영역 색. 비유클리드 출구(밖/노란테이블/결혼식장/일방통행/텔레포트)는 "포털" 커넥터로 별도 표기.
- 좌표는 빌드타임 1회 계산해 방 데이터에 캐시.

### U3. 인터랙션 강화 `[UI][소~중]`
- 오브젝트/몬스터 호버 정보, 클릭 대상 지정(공격/줍기), 명령 자동완성.
