# A4 이동·방·출구 의미론

> 무한의 이동 규칙, 방·출구 데이터 모델, 출구/방 플래그의 *실제 강제 위치*, 문·열쇠 상태머신, 존 구조를 oracle에서 규명한다. 인메모리 월드 모델·automap·방 단위 채널 결정(이슈 #14)의 입력. 이슈 #4. 출처는 `legacy/muhan/src`(EUC-KR, byte-level)와 변환 산출물 `data/world/rooms.json`(방 2341). 코드 이식이 아니라 동작 추출.

## 개요

무한의 월드는 **좌표 없는 방향성 그래프**다. 방은 노드, 출구는 *방향 이름 → 대상 방번호*의 간선이다(`exit_->room`). 좌표(x/y/z)는 **데이터에 존재하지 않는다.** 이동은 **순차 게이트 건틀릿** — 출구를 이름으로 찾고, 십수 개의 거부 조건을 순서대로 통과한 뒤, `del_ply_rom`/`add_ply_rom`으로 플레이어를 한 방의 연결 리스트에서 빼서 다른 방의 리스트에 넣는 **리스트 재배치**다. 디스크의 방 파일은 정적 콘텐츠가 아니라 **변경 가능한 라이브 상태**(문 개폐·재출현 타이머가 기록되고 evict 시 write-back)이며, 이는 1993년 RAM 제약의 산물(형상)이지 게임 규칙이 아니다.

핵심 분리: **그래프 구조·게이트 의미·플래그 값은 콘텐츠**(충실히 이식), **디스크-as-캐시·연결 리스트·게이트 코드 중복·좌표 부재는 형상**(재설계).

## 1. 이동 = 순차 게이트 건틀릿 (콘텐츠)

라이브 이동의 정본은 `move()`(`command2.c:284`)다. 방향 입력 정규화(`2`/`ㄴ`→`남` 등)는 **A3 §2 소관**이며 여기서는 정규화된 출구명(`tempstr`) 이후만 다룬다. 게이트는 다음 순서로 평가되고, 하나라도 걸리면 즉시 거부·이동 취소된다:

| 순서 | 게이트 | 조건 | 거부 출처 |
|---|---|---|---|
| 1 | 출구 존재 | 방 출구 리스트 선형 탐색, `XNOSEE`면 안 보임 | command2.c:347 "길이 막혀 있습니다" |
| 2 | 침묵 | `PSILNC` | :367 |
| 3 | 전투 중 | `ply_is_attacking` | :372 "싸우는 중에는 이동할 수 없습니다" |
| 4 | 잠김 | `XLOCKD` | :387 "문이 잠겨 있습니다" |
| 5 | 닫힘 | `XCLOSD` | :391 "문이 닫혀 있습니다" |
| 6 | 비행 필요 | `XFLYSP` && !`PFLYSP` | :395 |
| 7 | 야간 전용 | `XNGHTO` && (6<t<20) | :401 (t=`Time%24`) |
| 8 | 주간 전용 | `XDAYON` && (t<6‖t>20) | :406 |
| 9 | 출구 경비 | `XPGUAR` + 방에 `MPGUAR` 몬스터 (PINVIS·class≥SUB_DM 예외) | :411 |
| 10 | 여성 전용 | `XFEMAL` && `PMALES` | :428 |
| 11 | 남성 전용 | `XMALES` && !`PMALES` | :433 |
| 12 | 무소지 전용 | `XNAKED` && `weight_ply>0` | :438 "뭘 가지고는 들어갈수 없습니다" |
| 13 | 등반 | `XCLIMB`/`XREPEL` && !`PLEVIT` → 낙하 확률(`XDCLIM`이면 +50), 실패 시 피해·사망 가능 | :443 |
| 14 | 은신 유지 | thief/assassin이 `PHIDDN`이면 은신 성공 굴림(level·dex), 실패 시 `MBLOCK` 몬스터가 차단 가능 | :467 |
| — | 흔적 기록 | !`RPTRAK`이면 `rom->track = tempstr` (추적용) | :503 |
| — | 대상 방 적재 | `load_rom(exit->room)`; 적재 실패 시 `rom==old_rom` → "지도가 없습니다"(dangling) | :510 |
| 15 | 레벨 하한 | `rom->lolevel > level` (class<INVINCIBLE 예외) | :519 |
| 16 | 레벨 상한 | `level > rom->hilevel` && hilevel≠0 (class<CARETAKER 예외) | :524 |
| 17 | 정원 | `RONEPL`/`RTWOPL`/`RTHREE` + 가시 플레이어 수 초과 | :530 |
| 18 | 패거리 전용 | `RFAMIL` && !`PFAMIL` | :535 |
| 19 | 패거리 사유 | `RONFML` && `daily[DL_EXPND].max != rom->special` | :539 |
| 20 | 결혼/사유지 | `RONMAR` && `daily[DL_MARRI].max != rom->special`, 초대 목록(`invite_<special>`) 폴백 | :543 |

통과 시: 출발 broadcast → `del_ply_rom`/`add_ply_rom`(리스트 재배치) → **추종자**(`first_fol`) 따라 이동 → 출발 방의 **적대 몬스터** 추격 굴림(dex 비교) → `check_traps`. 

> **상단 죽은 코드 2건**(라이브 동작 아님): ① `LT_MOVED` 기반 이동 딜레이 블록 전체가 주석 처리됨 — A1이 기록한 `LT_MOVED` 슬롯은 *현재 미사용*. 라이브 이동 속도 제한은 게이트 3(전투 중)뿐. ② numpad/jamo→대각선 정규화 블록 주석 처리(A3 §2-2). 이식 대상은 죽은 코드가 아니라 **라이브 게이트 순서·의미**다.

**정렬 게이트 부재 (이슈 가설 정정)**: 이슈는 "정렬 게이트"를 가설로 들었으나, `move()`·`go()`·`flee()` 어디에도 alignment 검사가 없다. 정렬은 `PKNOWA`(간파술)로 몬스터 광채(`alignment<0`→붉은/푸른) *표시*에만 쓰인다(room.c:690). 실제 진영 게이트는 **성별(XFEMAL/XMALES)·왕국·패거리(RFAMIL/RONFML)·결혼(RONMAR)**이다.

## 2. 출구 플래그 — 강제 위치별 분류 (콘텐츠)

플래그는 byte 배열에 비트로 저장되고 `F_ISSET(p,f) = flags[f/8] & (1<<(f%8))`로 읽는다(`mtype.h:566`). exit는 `flags[4]`(32비트), room은 `flags[8]`(64비트). 헤더 주석이 아니라 **실제 `F_ISSET` 강제 위치**로 분류했다(헤더에만 있고 안 읽히는 플래그는 dead로 표기). 괄호 안은 `data/world` 실측 출현 수.

| 플래그(비트) | 헤더 의미 | 강제 위치 | 분류 |
|---|---|---|---|
| `XLOCKD`(2, 45) / `XCLOSD`(3, 77) | 잠김 / 닫힘 | move·go 게이트 + 문 상태머신 | **통행 게이트(라이브)** |
| `XLOCKS`(4, 56) / `XCLOSS`(5, 91) | 잠글수있음 / 닫을수있음 | lock/closeexit 가능 조건 + `check_exits` 타이머 재잠금·재닫힘 | **상태 능력(라이브)** |
| `XUNPCK`(6, 30) | 자물쇠 못땀 | picklock에서 확률 0 | **통행 게이트(라이브)** |
| `XNAKED`(7) | 무소지만 | move·go·flee·sneak 게이트 | **통행 게이트** |
| `XCLIMB`(8) / `XREPEL`(9) / `XDCLIM`(10) | 등반 장비/매우 어려움 | 4경로 낙하 굴림 | **통행 게이트** |
| `XFLYSP`(11, 14) | 비행 필요 | 4경로 게이트 | **통행 게이트** |
| `XFEMAL`(12, 3) / `XMALES`(13, 3) | 성별 전용 | move·flee 게이트 | **통행 게이트** |
| `XNGHTO`(16, 3) / `XDAYON`(17) | 야간/주간 전용 | move·go·flee (`Time%24`) | **통행 게이트(시간)** |
| `XPGUAR`(18, 64) | 수동 경비 | move·go·flee + 방의 `MPGUAR` 몬스터 | **통행 게이트(몬스터 연동)** |
| `XSECRT`(0, 46) | 비밀 | display_rom 숨김 + search로 발견(command2.c:1784) | **가시성(통행은 허용)** |
| `XINVIS`(1, 26) | 투명 | display_rom·find_ext 숨김(`PDINVI` 예외) | **가시성** |
| `XNOSEE`(19, 1) | 못봄/못씀 | display_rom 숨김 **+ move 이름 탐색 제외** | **가시성+통행 게이트** |
| `XPLDGK`(14) | pledge 전용 | **dm2.c 빌더 표시 전용** — 이동 미강제 | **dead(통행)** |
| `XKNGDM`(15) | 왕국 0/1 길 | **dm2.c 빌더 표시 전용** — 이동 미강제 | **dead(통행)** |
| `XKNDM1`(20) / `XKNDM2`(21) | 왕국 1/2번 길 | **어디서도 안 읽힘** | **완전 dead** |

핵심 구분 — **가시성 ≠ 통행 가능**: `XSECRT`·`XINVIS`는 출구 목록에서 숨길 뿐 *이름을 알면 걸어서 통과*된다(move의 이름 탐색은 `XNOSEE`만 차단). 이것이 비밀통로 발견 메커니즘(§5 search 연동)이다. `XNOSEE`만이 가시성과 통행을 동시에 막는다. dead 플래그(XKNDM1/2 등)는 A3가 찾은 죽은 대각선 별칭·`get_exit_char`와 같은 부류 — 데이터엔 의미가 있을 수 있으나 **엔진이 읽지 않으므로 이식 대상이 아니다.**

## 3. 문·열쇠 = 5플래그 상태머신 (콘텐츠)

문은 별도 엔티티가 아니라 **출구의 플래그 조합**이다. 상태 2비트(`XCLOSD`·`XLOCKD`) + 능력 3비트(`XCLOSS`·`XLOCKS`·`XUNPCK`)로 상태머신을 이룬다. 명령은 `command6.c:365–722`:

```
        openexit (요구: !XLOCKD)            lock (요구: XLOCKS + XCLOSD + 열쇠)
   ┌──────────────◄───────────────┐   ┌──────────────◄──────────────┐
[열림]                          [닫힘]                            [잠김]
   └──────────────►───────────────┘   └──────────────►──────────────┘
       closeexit (요구: XCLOSS)            unlock (요구: 열쇠)  /  picklock (도둑)
```

- **openexit**: `XLOCKD`면 거부, `XCLOSD` 해제, `ltime.ltime=now`(타이머 리셋).
- **closeexit**: `XCLOSS` 능력 필요, `XCLOSD` 설정.
- **lock**: `XLOCKS` + `XCLOSD`(먼저 닫혀야) + 열쇠 일치 → `XLOCKD` 설정.
- **unlock**: `XLOCKD` + 열쇠 → `XLOCKD` 해제, 열쇠 `shotscur--`, 타이머 리셋.
- **picklock**: **도둑(THIEF) 전용**, `LT_PICKL` 쿨다운 10초, 성공률 = level·dex 기반, `XUNPCK`면 확률 0(불가). 성공 시 `XLOCKD` 해제.

**열쇠 매칭 규칙(중요)**: 열쇠는 이름이 아니라 숫자로 매칭한다 — `obj->type == KEY` && `obj->ndice == exit->key`(`command6.c:512,598`). 즉 출구의 `key` 필드(char, parseRoom 오프셋 40)와 열쇠 오브젝트의 `ndice` 필드(주사위 수 필드를 열쇠 ID로 전용)가 같아야 한다. 열쇠는 `shotscur`로 사용 횟수가 제한되며 0이면 부서진다.

**타이머 자동 재잠금/재닫힘**: `check_exits()`(`room.c:469`)는 `XLOCKS`/`XCLOSS` 출구가 `ltime.ltime + ltime.interval < now`이면 자동으로 `XLOCKD`/`XCLOSD`를 재설정한다. 즉 열고 들어간 문은 `interval`초 후 다시 닫히고 잠긴다 — 출구의 `ltime`(`lasttime` 12B)이 이 타이밍을 인코딩한다(A1의 `lasttime` 모델과 동형).

## 4. 방 플래그 — 기능별 분류 (콘텐츠)

room `flags[8]`(64비트) 실측 분포(상위, 방 2341 기준). **강제 서브시스템**으로 분류 — 이동이 직접 보는 것과 다른 시스템(마법·상점·전투)이 보는 것을 구분한다.

| 범주 | 플래그(실측 수) | 강제 위치 |
|---|---|---|
| **이동 게이트** | `RONEPL`(43)·`RTWOPL`(14)·`RTHREE`(27) 정원, `RFAMIL`(0*)·`RONFML`·`RONMAR`·`RMARRI` 진영/결혼 | move §1 게이트 17–20 |
| **레벨 게이트** | `lolevel`/`hilevel` 필드(플래그 아님; 게이트 방 39개) | move §1 게이트 15–16 |
| **환경/가시성** | `RDARKR`(188 항상 어둠)·`RDARKN`(186 야간 어둠) | display_rom: 광원·종족(ELF/DWARF) 없으면 방 안 보임 |
| **위험 방(틱 피해)** | `RPHARM`(111)·`RPPOIS`(7)·`RPMPDR`(19)·`RPBEFU`(37) | update 틱(A1 `update_active` 계열) — A7/전투 소관 |
| **마법 게이트** | `RNOTEL`(792)·`RNOMAG`(61)·`RNOPOT`(25)·`RNOLEA`(648 소환금지)·`RPMEXT` | 마법 서브시스템 — **A6 소관** |
| **PvP/안전** | `RNOKIL`(36 안전지대)·`RPTRAK`(31 영구 흔적) | 전투/추적 — A5 소관 |
| **시설(특수 방)** | `RSHOPP`(17)·`RPAWNS`(1)·`RDUMPR`(2)·`RBANK`(2)·`RPOSTO`(1)·`RTRAIN`·`RFORGE`·`RHEALR`(36)·`RELECT` | 각 명령(상점/은행/훈련) — A2/A8 소관 |
| **속성 realm** | `REARTH`/`RWINDR`/`RFIRER`/`RWATER` | 마법 효과 — A6 소관 |
| **로그인** | `RNOLOG`(83 로그인 불가) | 세션 — A12 소관 |

A4가 *소유*하는 것은 이동 게이트·레벨 게이트·환경(어둠) 가시성이다. 나머지(`RNOTEL` 792개 등)는 방 데이터에 살지만 강제는 타 서브시스템이므로 해당 분석에 위임하되, **방이 이 플래그들을 운반한다는 사실**(인메모리 방 모델이 64비트 플래그를 전부 보존해야 함)만 여기서 못박는다.

(*) `RFAMIL` 실측 0 — 패거리존 플래그는 데이터에 미배치(기능은 코드에 존재). 빌더 미사용 흔적.

## 5. 트랩 & 비밀통로 (콘텐츠)

**트랩**: 방의 `trap`(char) + `trapexit`(short) 필드. `check_traps()`(`room.c:772`)가 *방 진입 시* 발동, `mrand` vs dex(또는 int) 내성 + `PPREPA`(준비/조심) 면제. 7종(`mtype.h:292`):

| trap | 효과 | 강제이동 |
|---|---|---|
| `TRAP_PIT`(1, 17개) | 구덩이 → `trapexit`로 추락 + 피해(PLEVIT 면제) | ✅ trapexit |
| `TRAP_DART`(2, 4개) | 독화살 피해 + `PPOISN` | — |
| `TRAP_BLOCK`(3, 5개) | 낙석, hpmax/3 피해 | — |
| `TRAP_MPDAM`(4) | mp 절반 + 소량 hp 피해 | — |
| `TRAP_RMSPL`(5, 1개) | 모든 버프 주문 해제(interval=0) | — |
| `TRAP_NAKED`(6) | 전 장비 상실(`lose_all`) | — |
| `TRAP_ALARM`(7, 4개) | `trapexit` 방의 경비 몬스터 소환·적대화 | (몬스터 이동) |

> 실측에 `trap=49` 1건 — 정의 범위(1–7) 밖. `check_traps`의 `default: return` 분기로 **무동작**되는 데이터 잔재(garbage). 변환은 보존하되 엔진은 무시한다.

**비밀통로**: `XSECRT` 출구는 display에서 숨겨지고(§2) `search` 명령(`command2.c:1784`)으로 `mrand` 확률 발견된다. 발견 후에도 플래그는 유지되지만 플레이어가 *이름을 알게 되어* 통과 가능 — 통행 자체는 항상 열려 있었다(move가 XSECRT를 막지 않으므로). 발견은 가시성 전환일 뿐이다.

## 6. 비유클리드 출구 — 그래프는 물리 공간이 아니다 (콘텐츠)

월드는 좌표 그래프가 아니라 **임의 간선 그래프**다. 실측·코드 근거:

- **일방통행 6.3%**(339/5353): 출구 A→B에 대해 B에 A로 돌아오는 출구가 없는 간선이 339개. 그중 327개는 의도된 단방향 통로, **12개는 진짜 dangling**(대상 방번호의 raw 파일조차 없음: 45·811·818·820·823·2012·2022·2024·2027·4293·7174·8302). dangling은 원본에서도 `load_rom` 실패 → `rom==old_rom` → "그쪽으로 지도가 없습니다"(command2.c:511)로 처리되는 **깨진 출구**다.
- **텔레포트(공간이동술/STELEP)**: `magic4.c:262`. 대상 = `mrand(1, RMAX-1)` **완전 랜덤 방**, `RNOTEL`·레벨 게이트 방을 거부할 때까지 재추첨. 인접성과 무관한 순간이동. `RNOTEL`(792개)이 도착지에서 이를 차단한다.
- **함정 강제이동**: `TRAP_PIT`·`TRAP_ALARM`이 `trapexit`로 비인접 이동(§5).
- **방향의 비대칭성**: 같은 방향 쌍(동↔서)이 강제되지 않음 — A→B가 "북"이어도 B→A가 "남"일 보장이 없다. 방향 이름은 **간선 라벨**일 뿐 기하 좌표가 아니다.

→ automap은 좌표를 *읽을* 수 없다. 그래프 위상 + 방향 힌트로 *합성*하되, 일방통행·비대칭·텔레포트를 **위상 예외로 표현**해야 한다(§아키텍처).

## 7. 존 구조 = 방번호/1000 디렉터리 샤딩 (콘텐츠/형상)

경로 공식은 `sprintf(file, "%s/r%02d/r%05d", ROOMPATH, index/1000, index)`(`files2.c:86`). 즉 **존 = `방번호/1000`**, 디렉터리 `r00`(0–999)·`r01`(1000–1999)… 방 ID의 진짜 출처는 **로드 경로 번호**이며 구조체 `rom_num`은 적재 시 `index`로 덮어쓰여진다(`files2.c:99`) — CLAUDE.md의 "rom_num은 stale, orphan 제외" 규칙의 코드 근거다.

실측 존 분포(정본 2341): `r00`:790 `r01`:72 `r02`:342 `r03`:498 `r04`:141 `r05`:33 `r06`:335 `r07`:3 `r08`:127. 존은 *좌표 영역이 아니라 콘텐츠 묶음/번호 대역*이다(존 7에 3개뿐인 점이 기하적 영역이 아님을 보여줌). 존 *경계 의미*(자연 구역)는 콘텐츠로 보존하되, `r%02d/r%05d` 파일 경로는 형상(DB 컬렉션/인덱스로 대체).

## 8. 이동 경로 4중 복제 (형상)

게이트 건틀릿(§1)은 **네 함수에 거의 동일하게 복붙**돼 있다:

| 함수 | 출처 | 출구 선택 | 특이점 |
|---|---|---|---|
| `move` | command2.c:284 | 방향어(`str[0]`) | 정본 방향 이동 |
| `go` | command6.c:76 | 명명 출구(`str[1]`, "가 <출구>") | move 게이트 전체 복제 |
| `flee` | command7.c:19 | **확률적 랜덤**(가시 출구 순회, 65%+dex 굴림) | 전투 탈출, 도착 후 레벨·정원 재검사로 튕김 |
| `sneak` | command10.c:17 | 방향어 | 은신 이동, 동일 건틀릿 |

`XNAKED`·`XPGUAR`·`XCLIMB`·`XFLYSP` 등의 검사가 4곳에 중복 정의됐다(A3가 `move`의 방향 정규화 복제를 찾은 것과 같은 패턴). 신규 스택은 **단일 `tryMove(actor, exit, mode)` 경로**로 통합하고 mode(`directional`/`named`/`flee`/`sneak`)로 분기한다 — 게이트 *순서·의미*는 콘텐츠로 보존하되 *4중 코드*는 형상으로 제거한다.

> `flee`에 `F_ISSET(xp->ext, 52)` 매직 비트 사용(command7.c:78). 비트 52는 exit `flags[4]`(32비트) 범위 밖 → `ltime` 바이트를 읽는 **경계 밖 접근(latent bug)**. 이식 시 재현하지 않는다.

## 9. load_rom = 디스크-as-라이브-상태 (형상, 전량 재설계)

`load_rom`(`files2.c:64`)은 lazy-load + LRU + write-back 캐시다:

1. `Rom[index].rom`이 있으면 LRU 큐 앞으로(`front_queue`) + 포인터 반환(캐시 히트).
2. 없으면 디스크에서 `read_rom` → malloc → 캐시 등록 → 큐 뒤로(`put_queue`).
3. 캐시 크기 > `RQMAX`이면 LRU 뒤에서 evict — **단, 플레이어가 있는 방(`first_ply`)은 보존**. evict 시 `write_rom(…, PERMONLY)`로 **디스크에 되써** 변경(문 상태·`beenhere`·재출현 타이머)을 영속화하고 `~` 백업 생성.
4. 매 적재 시 `add_permobj_rom`으로 재출현 아이템 채움.

이는 **메모리가 부족한 1993년의 페이징 전략**이다 — 디스크 파일이 라이브 상태의 backing store다. 2341개 방(`rooms.json` 2.4MB)은 현대 RAM에 통째로 상주 가능하므로 이 메커니즘 전체를 버린다. 신규 스택: **인메모리 객체 그래프(방 노드 + 출구 간선)를 부팅 시 전량 로드**, 변경분만 MongoDB에 비동기 영속화. `Rom[]` 배열·LRU 큐·write-back·`~` 백업은 형상으로 삭제.

## 아키텍처 함의 (이슈 #14 입력)

**인메모리 월드 모델**: 방은 부팅 시 전량 로드되는 객체 노드, 출구는 `{name, targetRoomId, flags, key, timer}` 간선이다. `Rom[]`+LRU 폐기 — 2341방은 통째로 상주. 플레이어/몬스터/아이템은 방 노드의 멤버 컬렉션(원본 `first_ply`/`first_mon`/`first_obj` 4-리스트에 대응)으로 표현하되 연결 리스트가 아닌 Set/배열. 방 상태 변경(문 개폐·재출현)은 메모리에서 일어나고 MongoDB로 비동기 영속화한다.

**automap 좌표화**: 데이터에 좌표가 없으므로(§6) automap은 **그래프에서 좌표를 합성**한다. 단서: (a) 기본 방향 6어(동서남북위밑)는 격자 변위로 해석 가능 — 원본도 `display_rom`의 PNOEXT 분기에서 **ASCII 나침반 미니맵**(동→우/서→좌/남·북→세로축/위·밑 라벨, room.c:611)을 이미 그린다. 이것이 "기본 방향은 2D+층 격자로 매핑된다"는 *설계 의도의 증거*다. (b) 명명 출구·대각선·일방통행·텔레포트는 격자에 안 맞으므로 **위상 예외 간선**으로 표시. 권장: BFS로 기본 방향 변위를 누적해 좌표를 *추정*하고, 충돌(같은 좌표에 두 방)·비대칭은 예외 렌더로 처리. 좌표는 표시용 파생값이지 정본이 아니다.

**방 단위 채널**: `broadcast_rom(fd, rom_num, msg)`(원본 전역에서 사용)은 *같은 방 점유자에게만 메시지 방송* — 방이 곧 pub/sub 채널이다. `del/add_ply_rom`이 채널 구독 변경이다. 신규 스택: 각 방을 WebSocket 룸/채널로 매핑, 이동 = `leave(oldRoom)`+`join(newRoom)`. 방송 대상은 방의 현재 멤버 집합. 어둠(`RDARKR`/`RDARKN`)·가시성(`PINVIS`/`PHIDDN`) 필터는 채널 송신 시점 가시성 검사로 이식.

**결정 필요(#14)**: ① 좌표 합성을 서버가 권위적으로 보유할지 클라이언트 렌더 책임으로 둘지(현 판단: 좌표는 클라이언트 파생, 서버는 그래프만 권위). ② 문/출구 타이머 재잠금(§3)을 A1 중앙 1Hz 틱의 `update_exit`에 실을지 출구별 스케줄로 둘지(현 판단: A1 모델대로 중앙 틱에서 `check_exits` 일괄 평가).
