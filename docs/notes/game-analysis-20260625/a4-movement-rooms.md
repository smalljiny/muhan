# A4 이동·방·출구 의미론

> 무한의 다음 내용을 오라클에서 정리한다.
> - 이동 규칙
> - 방·출구 데이터 모델
> - 출구/방 플래그가 *실제로 검사되는 위치*
> - 문·열쇠 상태머신
> - 존 구조
>
> 인메모리 월드 모델, automap, 방 단위 채널을 결정할 때(이슈 #14) 참고한다. 이슈 #4. 출처는 `legacy/muhan/src`(EUC-KR, byte-level)와 변환 산출물 `data/world/rooms.json`(방 2341)이며, 코드를 이식하지 않고 동작만 추출한다.

## 개요

무한의 월드는 **좌표 없는 방향성 그래프**다. 방은 노드이고, 출구는 *방향 이름 → 대상 방번호*로 이어지는 간선이다(`exit_->room`). 데이터에는 좌표(x/y/z)가 없다.

이동은 순차 게이트 검사를 거친 뒤 **리스트를 재배치**하는 방식이다. 먼저 출구를 이름으로 찾고, 십수 개의 거부 조건을 순서대로 통과해야 한다. 그다음 `del_ply_rom`/`add_ply_rom`으로 플레이어를 한 방의 연결 리스트에서 빼서 다른 방의 리스트에 넣는다.

디스크의 방 파일은 정적 콘텐츠가 아니라 **변경 가능한 라이브 상태**다. 문 개폐와 재출현 타이머가 기록되고, evict될 때 write-back된다. 이는 1993년 RAM 제약 때문에 생긴 원작의 구현 방식일 뿐 게임 규칙이 아니다.

핵심 분리:
- **콘텐츠(충실히 이식):** 그래프 구조, 게이트 의미, 플래그 값.
- **구현 방식(재설계):** 디스크를 캐시로 쓰는 구조, 연결 리스트, 게이트 코드 중복, 좌표가 없다는 점.

## 1. 이동 = 순차 게이트 검사 (콘텐츠)

라이브 이동의 기준은 `move()`(`command2.c:284`)다. 방향 입력 정규화(`2`/`ㄴ`→`남` 등)는 **A3 §2 담당**이므로, 여기서는 출구명이 정규화된 뒤(`tempstr`)부터 다룬다. 게이트는 다음 순서로 평가된다. 하나라도 걸리면 즉시 거부되고 이동이 취소된다.

| 순서 | 게이트 | 조건 | 거부 출처 |
|---|---|---|---|
| 1 | 출구 존재 | 방 출구 리스트 선형 탐색, `XNOSEE`면 안 보임 | command2.c:347 "길이 막혀 있습니다" |
| 2 | 침묵 | `PSILNC` | :367 |
| 3 | 전투 중 | `ply_is_attacking` | :372 "싸우는 중에는 이동할 수 없습니다" |
| 4 | 잠김 | `XLOCKD` | :387 "문이 잠겨 있습니다" |
| 5 | 닫힘 | `XCLOSD` | :391 "문이 닫혀 있습니다" |
| 6 | 비행 필요 | `XFLYSP` && !`PFLYSP` | :395 |
| 7 | 야간 전용 | `XNGHTO` && (6<t<20) | :401 (t=`Time%24`) |
| 8 | 주간 전용 | `XDAYON` && (t<6‖t>20) | :406 |
| 9 | 출구 경비 | `XPGUAR` + 방에 `MPGUAR` 몬스터 (PINVIS·class≥SUB_DM 예외) | :411 |
| 10 | 여성 전용 | `XFEMAL` && `PMALES` | :428 |
| 11 | 남성 전용 | `XMALES` && !`PMALES` | :433 |
| 12 | 무소지 전용 | `XNAKED` && `weight_ply>0` | :438 "뭘 가지고는 들어갈수 없습니다" |
| 13 | 등반 | `XCLIMB`/`XREPEL` && !`PLEVIT` → 낙하 확률(`XDCLIM`이면 +50), 실패 시 피해·사망 가능 | :443 |
| 14 | 은신 유지 | thief/assassin이 `PHIDDN`이면 은신 성공 굴림(level·dex), 실패 시 `MBLOCK` 몬스터가 차단 가능 | :467 |
| — | 흔적 기록 | !`RPTRAK`이면 `rom->track = tempstr` (추적용) | :503 |
| — | 대상 방 로드 | `load_rom(exit->room)`; 로드 실패 시 `rom==old_rom` → "지도가 없습니다"(dangling) | :510 |
| 15 | 레벨 하한 | `rom->lolevel > level` (class<INVINCIBLE 예외) | :519 |
| 16 | 레벨 상한 | `level > rom->hilevel` && hilevel≠0 (class<CARETAKER 예외) | :524 |
| 17 | 정원 | `RONEPL`/`RTWOPL`/`RTHREE` + 가시 플레이어 수 초과 | :530 |
| 18 | 패거리 전용 | `RFAMIL` && !`PFAMIL` | :535 |
| 19 | 패거리 사유 | `RONFML` && `daily[DL_EXPND].max != rom->special` | :539 |
| 20 | 결혼/사유지 | `RONMAR` && `daily[DL_MARRI].max != rom->special`, 초대 목록(`invite_<special>`) 폴백 | :543 |

통과하면 다음 순서로 진행된다. 출발 broadcast → `del_ply_rom`/`add_ply_rom`(리스트 재배치) → **추종자**(`first_fol`)가 따라 이동 → 출발 방의 **적대 몬스터**가 추격 굴림(dex 비교) → `check_traps`. 

> **상단 죽은 코드 2건**(라이브 동작 아님):
> - ① `LT_MOVED` 기반 이동 딜레이 블록 전체가 주석 처리돼 있다. 따라서 A1이 기록한 `LT_MOVED` 슬롯은 *현재 쓰이지 않는다*. 라이브에서 이동 속도를 제한하는 것은 게이트 3(전투 중)뿐이다.
> - ② numpad/jamo→대각선 정규화 블록도 주석 처리돼 있다(A3 §2-2).
>
> 이식할 것은 죽은 코드가 아니라 **라이브 게이트의 순서와 의미**다.

**성향 게이트 없음 (이슈 가설 정정)**: 이슈는 "성향 게이트"가 있다고 가정했다. 그러나 `move()`·`go()`·`flee()` 어디에도 alignment 검사가 없다. 성향은 `PKNOWA`(간파술)로 몬스터 광채(`alignment<0`→붉은/푸른)를 *표시*할 때만 쓰인다(room.c:690). 실제 진영 게이트는 **성별(XFEMAL/XMALES), 왕국, 패거리(RFAMIL/RONFML), 결혼(RONMAR)**이다.

## 2. 출구 플래그 — 강제 위치별 분류 (콘텐츠)

플래그는 byte 배열에 비트로 저장되고 `F_ISSET(p,f) = flags[f/8] & (1<<(f%8))`로 읽는다(`mtype.h:566`). exit는 `flags[4]`(32비트), room은 `flags[8]`(64비트)를 쓴다. 헤더 주석이 아니라 **실제로 `F_ISSET`이 검사되는 위치**를 기준으로 분류했다. 헤더에만 있고 읽히지 않는 플래그는 dead로 표기했다. 괄호 안 숫자는 `data/world`에서 실측한 출현 수다.

| 플래그(비트) | 헤더 의미 | 강제 위치 | 분류 |
|---|---|---|---|
| `XLOCKD`(2, 45) / `XCLOSD`(3, 77) | 잠김 / 닫힘 | move·go 게이트 + 문 상태머신 | **통행 게이트(라이브)** |
| `XLOCKS`(4, 56) / `XCLOSS`(5, 91) | 잠글수있음 / 닫을수있음 | lock/closeexit 가능 조건 + `check_exits` 타이머 재잠금·재닫힘 | **상태 능력(라이브)** |
| `XUNPCK`(6, 30) | 자물쇠 못땀 | picklock에서 확률 0 | **통행 게이트(라이브)** |
| `XNAKED`(7) | 무소지만 | move·go·flee·sneak 게이트 | **통행 게이트** |
| `XCLIMB`(8) / `XREPEL`(9) / `XDCLIM`(10) | 등반 장비/매우 어려움 | 4경로 낙하 굴림 | **통행 게이트** |
| `XFLYSP`(11, 14) | 비행 필요 | 4경로 게이트 | **통행 게이트** |
| `XFEMAL`(12, 3) / `XMALES`(13, 3) | 성별 전용 | move·flee 게이트 | **통행 게이트** |
| `XNGHTO`(16, 3) / `XDAYON`(17) | 야간/주간 전용 | move·go·flee (`Time%24`) | **통행 게이트(시간)** |
| `XPGUAR`(18, 64) | 수동 경비 | move·go·flee + 방의 `MPGUAR` 몬스터 | **통행 게이트(몬스터 연동)** |
| `XSECRT`(0, 46) | 비밀 | display_rom 숨김 + search로 발견(command2.c:1784) | **가시성(통행은 허용)** |
| `XINVIS`(1, 26) | 투명 | display_rom·find_ext 숨김(`PDINVI` 예외) | **가시성** |
| `XNOSEE`(19, 1) | 못봄/못씀 | display_rom 숨김 **+ move 이름 탐색 제외** | **가시성+통행 게이트** |
| `XPLDGK`(14) | pledge 전용 | **dm2.c 빌더 표시 전용** — 이동 미강제 | **dead(통행)** |
| `XKNGDM`(15) | 왕국 0/1 길 | **dm2.c 빌더 표시 전용** — 이동 미강제 | **dead(통행)** |
| `XKNDM1`(20) / `XKNDM2`(21) | 왕국 1/2번 길 | **어디서도 안 읽힘** | **완전 dead** |

핵심 구분 — **가시성 ≠ 통행 가능**: `XSECRT`·`XINVIS`는 출구 목록에서 숨기기만 한다. *이름을 알면 그대로 지나갈 수 있다*. move의 이름 탐색에서 제외되는 것은 `XNOSEE`뿐이기 때문이다. 이것이 비밀통로 발견 메커니즘이다(§5 search와 연결). 가시성과 통행을 동시에 막는 플래그는 `XNOSEE`뿐이다. dead 플래그(XKNDM1/2 등)는 A3가 찾은 죽은 대각선 별칭이나 `get_exit_char`와 같은 경우다. 데이터상으로는 의미가 있을 수 있지만 **엔진이 읽지 않으므로 이식하지 않는다.**

## 3. 문·열쇠 = 5플래그 상태머신 (콘텐츠)

문은 별도 엔티티가 아니라 **출구의 플래그 조합**이다. 상태 2비트(`XCLOSD`·`XLOCKD`)와 능력 3비트(`XCLOSS`·`XLOCKS`·`XUNPCK`)가 상태머신을 이룬다. 명령은 `command6.c:365–722`에 있다.

```
        openexit (요구: !XLOCKD)            lock (요구: XLOCKS + XCLOSD + 열쇠)
   ┌──────────────◄───────────────┐   ┌──────────────◄──────────────┐
[열림]                          [닫힘]                            [잠김]
   └──────────────►───────────────┘   └──────────────►──────────────┘
       closeexit (요구: XCLOSS)            unlock (요구: 열쇠)  /  picklock (도둑)
```

- **openexit**: `XLOCKD`면 거부, `XCLOSD` 해제, `ltime.ltime=now`(타이머 리셋).
- **closeexit**: `XCLOSS` 능력 필요, `XCLOSD` 설정.
- **lock**: `XLOCKS` + `XCLOSD`(먼저 닫혀야) + 열쇠 일치 → `XLOCKD` 설정.
- **unlock**: `XLOCKD` + 열쇠 → `XLOCKD` 해제, 열쇠 `shotscur--`, 타이머 리셋.
- **picklock**: 도둑(THIEF) 전용이다. `LT_PICKL` 쿨다운은 10초이고, 성공률은 level·dex에 따라 정해진다. `XUNPCK`면 확률이 0이라 불가능하다. 성공하면 `XLOCKD`를 해제한다.

**열쇠 매칭 규칙(중요)**: 열쇠는 이름이 아니라 숫자로 매칭한다. 조건은 `obj->type == KEY` && `obj->ndice == exit->key`다(`command6.c:512,598`). 즉 출구의 `key` 필드(char, parseRoom 오프셋 40)와 열쇠 아이템의 `ndice` 필드가 같아야 한다. 이 필드는 원래 주사위 수 필드인데 열쇠 ID로 바꿔 쓴다. 열쇠는 `shotscur`로 사용 횟수가 제한되며, 0이 되면 부서진다.

**타이머 자동 재잠금/재닫힘**: `check_exits()`(`room.c:469`)는 `XLOCKS`/`XCLOSS` 출구에서 `ltime.ltime + ltime.interval < now`이면 `XLOCKD`/`XCLOSD`를 자동으로 다시 설정한다. 즉 열고 들어간 문은 `interval`초 뒤에 다시 닫히고 잠긴다. 이 타이밍은 출구의 `ltime`(`lasttime` 12B)에 기록되며, A1의 `lasttime` 모델과 구조가 같다.

## 4. 방 플래그 — 기능별 분류 (콘텐츠)

room `flags[8]`(64비트)의 실측 분포다(상위 항목, 방 2341 기준). **플래그를 검사하는 서브시스템**별로 분류해, 이동이 직접 보는 플래그와 다른 시스템(마법·상점·전투)이 보는 플래그를 구분했다.

| 범주 | 플래그(실측 수) | 강제 위치 |
|---|---|---|
| **이동 게이트** | `RONEPL`(43)·`RTWOPL`(14)·`RTHREE`(27) 정원, `RFAMIL`(0*)·`RONFML`·`RONMAR`·`RMARRI` 진영/결혼 | move §1 게이트 17–20 |
| **레벨 게이트** | `lolevel`/`hilevel` 필드(플래그 아님; 게이트 방 39개) | move §1 게이트 15–16 |
| **환경/가시성** | `RDARKR`(188 항상 어둠)·`RDARKN`(186 야간 어둠) | display_rom: 광원·종족(ELF/DWARF) 없으면 방 안 보임 |
| **위험 방(틱 피해)** | `RPHARM`(111)·`RPPOIS`(7)·`RPMPDR`(19)·`RPBEFU`(37) | update 틱(A1 `update_active` 계열) — A7/전투 담당 |
| **마법 게이트** | `RNOTEL`(792)·`RNOMAG`(61)·`RNOPOT`(25)·`RNOLEA`(648 소환금지)·`RPMEXT` | 마법 서브시스템 — **A6 담당** |
| **PvP/안전** | `RNOKIL`(36 안전지대)·`RPTRAK`(31 영구 흔적) | 전투/추적 — A5 담당 |
| **시설(특수 방)** | `RSHOPP`(17)·`RPAWNS`(1)·`RDUMPR`(2)·`RBANK`(2)·`RPOSTO`(1)·`RTRAIN`·`RFORGE`·`RHEALR`(36)·`RELECT` | 각 명령(상점/은행/훈련) — A2/A8 담당 |
| **속성 realm** | `REARTH`/`RWINDR`/`RFIRER`/`RWATER` | 마법 효과 — A6 담당 |
| **로그인** | `RNOLOG`(83 로그인 불가) | 세션 — A12 담당 |

A4가 *담당*하는 것은 이동 게이트, 레벨 게이트, 환경(어둠) 가시성이다. 나머지(`RNOTEL` 792개 등)는 방 데이터에 있지만 다른 서브시스템이 검사하므로 해당 분석에 맡긴다. 다만 **방이 이 플래그들을 가지고 있다는 사실**은 여기서 확정한다. 즉 인메모리 방 모델은 64비트 플래그를 전부 보존해야 한다.

(*) `RFAMIL` 실측 0 — 패거리존 플래그는 데이터에 배치되지 않았다(기능은 코드에 있다). 빌더가 쓰지 않은 흔적이다.

## 5. 트랩 & 비밀통로 (콘텐츠)

**트랩**: 방의 `trap`(char)과 `trapexit`(short) 필드로 표현된다. `check_traps()`(`room.c:772`)가 *방에 들어올 때* 발동한다. `mrand`와 dex(또는 int)를 비교해 내성을 굴리고, `PPREPA`(준비/조심) 상태면 면제된다. 종류는 7가지다(`mtype.h:292`).

| trap | 효과 | 강제이동 |
|---|---|---|
| `TRAP_PIT`(1, 17개) | 구덩이 → `trapexit`로 추락 + 피해(PLEVIT 면제) | ✅ trapexit |
| `TRAP_DART`(2, 4개) | 독화살 피해 + `PPOISN` | — |
| `TRAP_BLOCK`(3, 5개) | 낙석, hpmax/3 피해 | — |
| `TRAP_MPDAM`(4) | mp 절반 + 소량 hp 피해 | — |
| `TRAP_RMSPL`(5, 1개) | 모든 버프 주문 해제(interval=0) | — |
| `TRAP_NAKED`(6) | 전 장비 상실(`lose_all`) | — |
| `TRAP_ALARM`(7, 4개) | `trapexit` 방의 경비 몬스터 소환·적대화 | (몬스터 이동) |

> 실측 데이터에 `trap=49`가 1건 있는데, 정의 범위(1–7) 밖이다. `check_traps`의 `default: return` 분기에 걸려 **아무 동작도 하지 않는** 데이터 잔재(garbage)다. 변환할 때는 보존하되 엔진은 무시한다.

**비밀통로**: `XSECRT` 출구는 display에서 숨겨지고(§2), `search` 명령(`command2.c:1784`)으로 `mrand` 확률에 따라 발견된다. 발견한 뒤에도 플래그는 그대로지만, 플레이어가 *이름을 알게 되어* 지나갈 수 있다. move가 XSECRT를 막지 않으므로 통행 자체는 처음부터 가능했다. 발견은 가시성만 바꿀 뿐이다.

## 6. 비유클리드 출구 — 그래프는 물리 공간이 아니다 (콘텐츠)

월드는 좌표 그래프가 아니라 **간선을 임의로 잇는 그래프**다. 실측과 코드에서 찾은 근거는 다음과 같다.

- **일방통행 6.3%**(339/5353): 출구 A→B가 있는데 B에서 A로 돌아오는 출구가 없는 간선이 339개다.
  - 그중 327개는 의도된 단방향 통로다.
  - **12개는 진짜 dangling**이다. 대상 방번호의 raw 파일조차 없다(45·811·818·820·823·2012·2022·2024·2027·4293·7174·8302).
  - dangling은 원본에서도 **깨진 출구**다. `load_rom`이 실패하면 `rom==old_rom`이 되고 "그쪽으로 지도가 없습니다"(command2.c:511)를 출력한다.
- **텔레포트(공간이동술/STELEP)**: `magic4.c:262`. 대상은 `mrand(1, RMAX-1)`로 뽑은 **완전 랜덤 방**이며, `RNOTEL` 방이나 레벨 게이트 방이 나오면 다시 뽑는다. 인접 여부와 상관없는 순간이동이다. 도착지의 `RNOTEL`(792개)이 이를 막는다.
- **함정 강제이동**: `TRAP_PIT`·`TRAP_ALARM`이 `trapexit`로 인접하지 않은 방으로 옮긴다(§5).
- **방향의 비대칭성**: 반대 방향 쌍(동↔서)이 보장되지 않는다. A→B가 "북"이어도 B→A가 "남"이라는 보장은 없다. 방향 이름은 **간선 라벨**일 뿐 기하 좌표가 아니다.

→ automap은 좌표를 데이터에서 *읽을* 수 없다. 그래프 위상과 방향 힌트로 좌표를 *합성*하고, 일방통행·비대칭·텔레포트는 **위상 예외로 표현**해야 한다(§아키텍처).

## 7. 존 구조 = 방번호/1000 디렉터리 샤딩 (콘텐츠/구현 방식)

경로 공식은 `sprintf(file, "%s/r%02d/r%05d", ROOMPATH, index/1000, index)`다(`files2.c:86`). 즉 **존 = `방번호/1000`**이고, 디렉터리는 `r00`(0–999), `r01`(1000–1999)… 순이다. 방 ID의 진짜 출처는 **로드 경로 번호**다. 구조체의 `rom_num`은 로드할 때 `index`로 덮어쓰인다(`files2.c:99`). CLAUDE.md의 "rom_num은 stale, orphan 제외" 규칙은 이 코드에 근거한다.

실측 존 분포(기준 데이터 2341): `r00`:790 `r01`:72 `r02`:342 `r03`:498 `r04`:141 `r05`:33 `r06`:335 `r07`:3 `r08`:127. 존은 *좌표 영역이 아니라 콘텐츠 묶음 또는 번호 대역*이다. 존 7에 방이 3개뿐이라는 점이 기하적 영역이 아님을 보여 준다. 존 *경계의 의미*(자연 구역)는 콘텐츠로 보존한다. 반면 `r%02d/r%05d` 파일 경로는 구현 방식이므로 DB 컬렉션/인덱스로 대체한다.

## 8. 이동 경로 4중 복제 (구현 방식)

§1의 게이트 검사는 **네 함수에 거의 그대로 복사**돼 있다.

| 함수 | 출처 | 출구 선택 | 특이점 |
|---|---|---|---|
| `move` | command2.c:284 | 방향어(`str[0]`) | 기준 방향 이동 |
| `go` | command6.c:76 | 명명 출구(`str[1]`, "가 <출구>") | move 게이트 전체 복제 |
| `flee` | command7.c:19 | **확률적 랜덤**(가시 출구 순회, 65%+dex 굴림) | 전투 탈출, 도착 후 레벨·정원 재검사로 튕김 |
| `sneak` | command10.c:17 | 방향어 | 은신 이동, 같은 게이트 검사 |

`XNAKED`·`XPGUAR`·`XCLIMB`·`XFLYSP` 등의 검사가 4곳에 중복 정의돼 있다. A3가 `move`에서 방향 정규화가 복제된 것을 찾은 것과 같은 패턴이다. 신규 스택은 **단일 `tryMove(actor, exit, mode)` 경로**로 통합하고 mode(`directional`/`named`/`flee`/`sneak`)에 따라 분기한다. 게이트의 *순서와 의미*는 콘텐츠로 보존하고, *4중 코드*는 원작의 구현 방식이므로 제거한다.

> `flee`는 `F_ISSET(xp->ext, 52)`라는 매직 비트를 쓴다(command7.c:78). 비트 52는 exit `flags[4]`(32비트) 범위 밖이라 `ltime` 바이트를 읽게 되는 **경계 밖 접근(latent bug)**이다. 이식할 때 재현하지 않는다.

## 9. load_rom = 디스크-as-라이브-상태 (구현 방식, 전량 재설계)

`load_rom`(`files2.c:64`)은 lazy-load + LRU + write-back 캐시다.

1. `Rom[index].rom`이 있으면 LRU 큐 앞으로 옮기고(`front_queue`) 포인터를 반환한다(캐시 히트).
2. 없으면 디스크에서 `read_rom` → malloc → 캐시 등록 → 큐 뒤에 넣는다(`put_queue`).
3. 캐시 크기가 `RQMAX`보다 크면 LRU 뒤쪽부터 evict한다. **단, 플레이어가 있는 방(`first_ply`)은 남긴다**. evict할 때는 `write_rom(…, PERMONLY)`로 디스크에 다시 써서 변경 내용(문 상태, `beenhere`, 재출현 타이머)을 영속화하고 `~` 백업을 만든다.
4. 로드할 때마다 `add_permobj_rom`으로 재출현 아이템을 채운다.

이는 **메모리가 부족하던 1993년의 페이징 전략**이다. 디스크 파일이 라이브 상태의 backing store 역할을 한다. 2341개 방(`rooms.json` 2.4MB)은 현대 RAM에 통째로 올려 둘 수 있으므로 이 메커니즘 전체를 버린다. 신규 스택은 **부팅할 때 인메모리 객체 그래프(방 노드 + 출구 간선)를 전부 로드**하고, 변경분만 MongoDB에 비동기로 영속화한다. `Rom[]` 배열, LRU 큐, write-back, `~` 백업은 원작의 구현 방식이므로 삭제한다.

## 아키텍처 시사점 (이슈 #14 입력)

**인메모리 월드 모델**: 방은 부팅할 때 전부 로드되는 객체 노드이고, 출구는 `{name, targetRoomId, flags, key, timer}` 간선이다. `Rom[]`과 LRU는 버린다. 2341개 방은 통째로 메모리에 둔다. 플레이어, 몬스터, 아이템은 방 노드의 멤버 컬렉션으로 표현하며, 원본의 `first_ply`/`first_mon`/`first_obj` 4-리스트에 대응한다. 다만 연결 리스트가 아니라 Set이나 배열을 쓴다. 방 상태 변경(문 개폐, 재출현)은 메모리에서 일어나고 MongoDB에 비동기로 영속화한다.

**automap 좌표화**: 데이터에 좌표가 없으므로(§6) automap은 **그래프에서 좌표를 합성**한다. 단서는 두 가지다.
- (a) 기본 방향 6개(동서남북위밑)는 격자 변위로 해석할 수 있다. 원본도 `display_rom`의 PNOEXT 분기에서 **ASCII 나침반 미니맵**을 이미 그린다(동→우/서→좌/남·북→세로축/위·밑 라벨, room.c:611). 이는 "기본 방향은 2D+층 격자로 매핑된다"는 *설계 의도를 보여 주는 증거*다.
- (b) 명명 출구, 대각선, 일방통행, 텔레포트는 격자에 맞지 않으므로 **위상 예외 간선**으로 표시한다.

권장 방식은 BFS로 기본 방향 변위를 누적해 좌표를 *추정*하고, 충돌(같은 좌표에 두 방)과 비대칭은 예외 렌더로 처리하는 것이다. 좌표는 표시용 파생값일 뿐 기준 값이 아니다.

**방 단위 채널**: `broadcast_rom(fd, rom_num, msg)`는 원본 곳곳에서 쓰이며, *같은 방에 있는 사람에게만 메시지를 방송*한다. 즉 방이 곧 pub/sub 채널이고, `del/add_ply_rom`은 채널 구독을 바꾸는 동작이다. 신규 스택은 각 방을 WebSocket 룸/채널로 매핑하고, 이동은 `leave(oldRoom)`+`join(newRoom)`으로 처리한다. 방송 대상은 방의 현재 멤버 집합이다. 어둠(`RDARKR`/`RDARKN`)과 가시성(`PINVIS`/`PHIDDN`) 필터는 채널로 보낼 때 가시성을 검사하는 방식으로 이식한다.

**결정 필요(#14)**:
- ① 좌표 합성 결과를 서버가 최종 기준으로 가질지, 클라이언트 렌더 책임으로 둘지. 현재 판단은 좌표는 클라이언트에서 파생하고, 서버는 그래프만 기준으로 갖는 것이다.
- ② 문/출구 타이머 재잠금(§3)을 A1 중앙 1Hz 틱의 `update_exit`에서 처리할지, 출구별 스케줄로 둘지. 현재 판단은 A1 모델대로 중앙 틱에서 `check_exits`를 일괄 평가하는 것이다.
