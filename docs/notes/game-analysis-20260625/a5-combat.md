# A5 전투 시스템

> 무한의 전투 공식(명중·피해·크리티컬·사망·경험치)과 전투 라운드가 *어떻게 진행되는지*를 oracle에서 규명한다. 밸런스 유지가 목적이므로 공식·수치는 충실히 이식하고 구현은 자유롭게 재설계한다. 이슈 #5. 출처는 `legacy/muhan/src`(EUC-KR, byte-level)와 변환 산출물 `data/world/creatures.json`(몬스터 템플릿 672). 코드 이식이 아니라 동작 추출.
>
> **정본 파일 정정(선결)**: 이슈는 전투 코드로 `comman5_old.c`(`attack`)를 지목했으나, **실제 컴파일·링크되는 파일은 `command5.c`**다. 근거: (a) `command5.o`(61988B)는 존재하고 `comman5_old.o`는 **부존재**, (b) `util/MAKEFILE:6` 오브젝트 링크 목록에 `command5.o`가 있고 `comman5_old`는 어디에도 없다. 두 파일의 `attack_crt`는 **단 두 곳만 다르다** — ① 명중식 `armor/10`(구) → **`armor/8`**(정본, `command5.c:231`), ② 인라인 HP 상태바 출력이 `display_status()` 호출로 리팩터. 피해·크리티컬·불발·내구도 로직은 바이트 동일. 본 노트의 모든 라인 번호·공식은 **`command5.c` 정본** 기준이며, `comman5_old.c`는 A4가 기록한 dead 플래그·죽은 코드와 같은 부류(디스크에 있으나 엔진이 읽지 않음)로 취급해 이식 대상에서 제외한다.

## 개요

무한의 전투는 **몬스터 틱 구동 라운드**다. 플레이어의 `attack` 명령은 전투를 *개시*할 뿐(단 1회 타격 + 적대 등록), 이후 라운드는 중앙 1Hz 틱의 `update_active`(A1)가 **활성 몬스터 리스트를 매초 순회**하며 각 몬스터를 자기 쿨다운(민첩 기반 2~3초)으로 때리고, 그 몬스터의 적 리스트에 오른 플레이어들이 **자동 반격**(`attack_crt`)하는 방식으로 전진한다. 플레이어에게 독립적 "초당 공격 스케줄러"는 없다 — 오프너 이후 플레이어 피해는 전부 몬스터 틱에 접힌 반격이다.

명중은 **`thaco - armor/8` 임계값을 난수 굴림이 넘으면 성공**하는 D&D THAC0 계보다(낮은 thaco·낮은 armor일수록 유리). 플레이어와 몬스터는 **같은 뼈대, 다른 스케일**을 쓴다 — 플레이어는 `mrand(1,30)`·피해에 무기 주사위+힘보너스+숙련, 몬스터는 `mrand(1,20)`·피해에 자기 주사위−방어경감. 결정적 비대칭 하나: **플레이어 thaco는 클래스·레벨·장비로 *계산*(`compute_thaco`)되는 파생값**이고, **몬스터 thaco는 템플릿에 *저장된 저작 데이터***(실측 중앙값 5)다.

핵심 분리: **공식·수치·라운드 박자·게이트 의미는 콘텐츠**(충실히 이식), **연결 리스트 순회·인라인 4중 복제·초 단위 폴링·미초기화 변수 버그는 형상**(재설계).

## 1. 전투 루프 구조 = 몬스터 틱 구동 + 플레이어 반격 (콘텐츠)

이슈가 "라운드 진행"으로 지목한 부분이며, 모든 공식이 매달리는 연결 조직이다. **플레이어는 능동 스케줄러가 없다** — `attack_crt(player, monster)`가 실행되는 경로는 오직 두 곳이다(전 소스 grep):

| 호출부 | 주체 | 성격 |
|---|---|---|
| `command5.c:89` (`attack` 명령) | 플레이어 | **오프너 1회** — 한 번 때리고 `add_enm_crt`로 적대 등록 |
| `update.c:512, 517, 569, 574` | 플레이어(반격) | 몬스터 틱 내부에서 그 몬스터의 적 리스트 플레이어들이 자동 반격 |

즉 라운드 진행의 정본은 `update.c`의 **`update_active(t)`**(`update.c:229`, A1이 "매초 전투 진행"으로 이월한 함수)다. 매초 `first_active`(활성 몬스터 `ctag` 연결 리스트)를 순회하며 몬스터마다:

| 순서 | 단계 | 조건/효과 | 출처 |
|---|---|---|---|
| 1 | 방 정리 | 방에 플레이어 없으면(`!first_ply`) `del_active` 후 스킵 | update.c:254 |
| 2 | 혼란 해제 | `LT(crt,LT_BEFUD)<t`면 `MBEFUD` 해제 | :259 |
| 3 | 자가 회복 | `LT_HEALS` 만료마다 `hpcur += MAX(1,hpmax/10)`, `mpcur += MAX(1,mpmax/6)`, **interval 60초** | :264 |
| 4 | 매혹 해제 | `LT_CHRMD` 만료 시 `MCHARM` 해제 | :277 |
| 5 | **공격 쿨다운 게이트** | `LT(crt,LT_ATTCK)>t`면 이번 몬스터 스킵 | :280 |
| 6 | 쿨다운 재설정 | `interval = (dexterity<20) ? 3 : 2` — **민첩<20이면 3초, 이상이면 2초 주기** | :285 |
| 7 | 스캐빈저 | `MSCAVE` + 20초 경과 + `mrand(1,100)<=15`면 방 바닥 아이템 줍기(`MHASSC` 설정) | :291 |
| 8 | 방황 despawn | 비-`MHASSC`·비-`MPERMT`·비-`MDMFOL` + 20초 + `mrand(1,100)<=traffic` + 적 없음이면 방 떠나 `free_crt` | :312 |
| 9 | 비전투 종료 | 적 없고 `MAGGRE`/`MGAGGR`/`MEAGGR` 전부 없으면 무행동 | :329 |
| — | (A) 적 있음 | `first_enm` → §3 공격 실행 | :334 |
| — | (B) 선공 | 공격성 플래그로 신규 타깃 선정 → §9 | :587 |

**라운드 케이던스 = 몬스터의 2~3초 틱**이지 플레이어 공격 주기가 아니다. 플레이어 오프너 1타 후, 몬스터가 자기 틱에 때리고 → 같은 틱 안에서 적 리스트의 플레이어들이 `attack_crt`로 반격한다(`update.c:502–523`·`560–580`, `NUMHITS≠0`일 때). 반격도 `attack_crt` 진입부의 플레이어 `LT_ATTCK` 쿨다운으로 재게이트되므로, 실효 플레이어 타격 빈도는 몬스터 틱과 자기 쿨다운의 교집합이다.

> **#14 결정 포인트**: 신규 스택에서 전투를 (a) 원본대로 **몬스터 구동 틱 + 플레이어 반격**으로 재현할지, (b) 플레이어에게도 독립 공격 루프를 줄지. 현 판단: 원본의 몬스터 구동 모델이 밸런스(공격 빈도·반격 타이밍)를 정의하므로 **A1의 매초 활성 리스트 순회 위에 그대로 재현**하되, 4중 인라인 복제(§) 코드는 통합한다.

## 2. 플레이어 근접 공격 = `attack_crt` (정본 `command5.c`) (콘텐츠)

플레이어 `attack` 명령(`command5.c:36`)의 진입 게이트: `class==0`(전투금지 직업) 거부, `LT_ATTCK` 쿨다운 대기, `cmnd->num<2` 또는 `PBLIND`면 대상 미지정 거부, `ply_is_attacking`(이미 교전 중) 거부, `find_crt`로 방의 몬스터→플레이어 순 대상 탐색. 통과 시 **`attack_crt(ply_ptr, crt_ptr)` 1회 호출**(`command5.c:89`).

`attack_crt`(`command5.c:103`) 본문 순서:

**쿨다운 설정** (`:131–138`): `lasttime[LT_ATTCK].ltime=t`; `interval=1`(무기/맨손 공통 — `PHASTE` 분기가 양쪽 다 `1`이라 **가속 무효 버그**), `PBLIND`면 `interval=6`. PvP(대상이 플레이어)면 뒤에서 `interval += 3`.

**대상 무적 플래그** (`:139–166`, 몬스터 한정): `MUNKIL`(해칠 수 없음) 거부, `MMGONL`(마법무기만) 거부, `MENONL`(마법무기 필요) + 플레이어 무기 `adjustment<1`이면 거부.

**PvP 게이트** (`:167–198`, 대상이 플레이어): §8 참조.

**다중 공격** (`:200–209`): `PUPDMG` 보유 + `(INVINCIBLE·level>100)‖class>INVINCIBLE`이면 `(level-97)/10 + mrand(0,3) > 2`일 때 `count++`; `class>INVINCIBLE` + `mrand(1,4)==1`이면 추가 `count++`. 초인 전용 연타.

`for(count)` 루프 안에서 매 타격:

**명중** (`command5.c:231–236`):
```
n = ply_ptr->thaco - crt_ptr->armor/8;     // 정본: /8 (구 백업은 /10)
if(F_ISSET(ply, PFEARS)) n += 2;
if(F_ISSET(ply, PBLIND)) n += 5;
if(mrand(1,30) >= n) { …명중… }            // 주석 "원래값 20" — d20→d30 완화
```

**피해** (`:237–259`), 클래스·장비별 분기:

| 조건 | 피해식 |
|---|---|
| 무기 장착 | `mdice(무기) + bonus[힘] + profic(ply, 무기type)/10` (+ 오프핸드 비-방어구면 `+ mdice(HELD)/10`) |
| BARBARIAN 또는 class>INVINCIBLE | `mdice(자기) + bonus[힘] + (level+3)/4` |
| 그 외 맨손 | `mdice(자기) + bonus[힘]` |
| MAGE/CLERIC | 무기 있으면 `mdice(무기)+bonus[힘]`, 없으면 `mdice(자기)+bonus[힘]` |
| 대상 class≥DM | `n = 0` (DM 무적) |

이후 `n = MAX(1,n)`. **PALADIN 정렬 보정**(`:261–270`): `alignment<0`이면 `n/=2`(악행 페널티), `alignment>250`이면 `n += mrand(1,3)`(선행 보너스).

**크리티컬·불발** (`:272–306`): `p = mod_profic(ply)`(§4, 대략 0~5).
- 크리: `mrand(1,100) <= p` **또는** 무기 `OALCRT` 플래그 → 초록 "치명타" + `n *= mrand(3,6)`(3~6배). 크리 시 무기 파괴 확률(`ONSHAT` 아니고 `mrand(1,100)<3` 또는 `OALCRT`, `ONEWEV` 아니면 `free_obj`).
- 불발: `mrand(1,100) <= (5-p)` + 무기 있고 `OCURSE` 아님 → 무기 낙하, `n=0`, `compute_thaco` 재계산.

**적용** (`:308–374`): 데미지 메시지 + `display_status`(HP 바), 무기 내구도 `!mrand(0,3)`(25%)면 `shotscur--`, `crt->hpcur -= n`. 몬스터면 `add_enm_dmg`(기여 누적) + 무기 숙련 획득 `addprof = MIN(m*experience/MAX(hpmax,1), experience)`. `hpcur<1`이면 `die(crt, ply)`(§7) 후 `return(1)`, 아니면 `check_for_flee`(죽은 코드, §13). 빗나가면 "허공을 쳤습니다".

**실측 근거**(data/world 몬스터 672): thaco 중앙값 5·p90 18(min −30 max 100), armor 중앙값 0·p90 90(min −127 max 127) → 명중 임계값 `thaco − armor/8`은 저레벨 몹에서 대체로 한 자릿수라 `mrand(1,30)`이 쉽게 넘는다. 즉 다수 접전은 명중이 기본이고 armor 높은(방어형) 몹만 회피가 유의미해진다.

## 3. 몬스터 근접 공격 = `update_active` 인라인 (콘텐츠)

몬스터는 `attack_crt`를 쓰지 않고 `update_active` 안에서 **자체 인라인 로직**으로 때린다(`update.c:334–585`). 타깃은 `first_enm->enemy`를 `find_crt`로 해석.

**주문 분기** (`:348–376`, `MMAGIC`): 시전 확률 `n=20`(또는 `MMAGIO`면 `proficiency[0]`), `mrand(1,100)<=n` + 비매혹이면 `crt_spell`(`update.c:654` — 아는 주문 중 `mrand`로 하나, offensive면 `offensive_spell`). 반환 2면 라운드 재시작, 1이면 근접 생략(주문이 그 라운드 공격), 0이면 근접 진행. **마법 데미지 공식 자체는 A6 소관**.

**명중** (`:373–383`):
```
n = crt_ptr->thaco - att_ptr->armor/8;
n = MAX(n, 1);
if(mrand(1,20) >= n) { …명중… }            // 플레이어보다 좁은 d20 굴림
```

**피해** (`:439–447`):
```
n = mdice(crt_ptr) - ((70 - att_ptr->armor)/5);   // armor 다른 스케일(70기준,/5)
if(n < 1) n = 1;
if(F_ISSET(crt, MBEFUD)) n = n/3;                 // 혼란 몬스터 1/3
att_ptr->hpcur -= n;
```

**플레이어 vs 몬스터 근접 대조**:

| 항목 | 플레이어 (`command5.c`) | 몬스터 (`update.c`) |
|---|---|---|
| 명중식 | `thaco − armor/8` | `thaco − armor/8` (동일) |
| 명중 굴림 | `mrand(1,30) >= n` | `mrand(1,20) >= n` (더 좁음 = 몬스터 명중률 높음) |
| 피해 | `mdice(무기/자기) + bonus[힘] + profic/10` | `mdice(자기) − (70−armor)/5` |
| 크리티컬 | 있음(`mod_profic`) | 없음(브레스/특수공격으로 대체) |
| 쿨다운 | `LT_ATTCK` interval 1(PvP +3, 실명 6) | interval 2(dex≥20)/3(dex<20) |
| thaco 출처 | **계산**(`compute_thaco`) | **저장 데이터**(템플릿) |

피해 실측(몬스터 672): `ndice` 중앙값 4·`sdice` 5·`pdice` 2 → 전형 몹 피해 ≈ `4d5+2`(평균 ~14), 단 보스급은 `sdice` 최대 492·`pdice` 최대 5700로 극단. `experience` 최대 666666.

## 4. 명중·방어 스택 (콘텐츠 — 테이블·공식)

명중/피해가 참조하는 보조 함수·테이블. **주사위·보너스 테이블은 전투 밸런스의 원천**이므로 값 전체를 이식한다.

**`dice(n,s,p)`**(`misc.c:454`) + 매크로 `mdice(a)=dice(a->ndice,a->sdice,a->pdice)`(`mtype.h:588`):
```
for(i=0;i<n;i++) p += mrand(1,s);   return p;    // p + n개의 s면체 합
```
**`mrand(a,b)`**(`mtype.h:587`): `[a,b]` **양끝 포함 정수 균등**.

**`bonus[64]`**(`global.c:57`) — 능력치(힘·민첩·신앙 등) 인덱싱, 값 −4~+7:
```
idx  0- 7:  -4 -4 -4 -3 -3 -2 -2 -1
idx  8-15:  -1 -1  0  0  0  0  1  1
idx 16-23:   1  2  2  2  3  3  3  3
idx 24-31:   4  4  4  4  4  5  5  5
idx 32-39:   5  5  5  6  6  6  6  6
idx 40-47:   6  6  6  6  7  7  7  7
idx 48-63:   7 (이하 전부 7)
```

**`compute_thaco`**(`player.c:1001`) — 플레이어 thaco 산출(파생값):
```
col = MIN(19, (level+3)/4 - 1);
thaco = thaco_list[class][col];
thaco -= 무기->adjustment;
thaco -= mod_profic(ply);
thaco -= bonus[strength];
thaco = MAX(하한, thaco);   // class<CARETAKER: level<101 → 0, 그 이상 → -5; DM계열 → -10
// (PBLESS -3은 대입 후라 미반영 = dead)
```
`thaco_list[13][20]`(`global.c:94`, 행=클래스 enum, 열=`(level+3)/4−1`) 발췌 — FIGHTER(4): `20,19,18,…,4,3,3,3`(레벨↑ 하강), MAGE(5): `20,20,19,…,13,13,11`(완만), INVINCIBLE(9): 전부 1, CARETAKER/SUB_DM/DM(10~12): 전부 −5. 낮을수록 명중 쉬움 → 전사계가 최상, 마법사계가 최약.

**`profic`/`mod_profic`**(`player.c:1120`/`1032`) — 무기 숙련. `profic`은 `proficiency[무기type]` 경험치가 클래스별 임계 테이블 `prof_array[12]`의 어느 구간인지로 0~약110%를 선형보간 반환(피해에 `/10` = 구간당 +1). `mod_profic`은 `profic(장착무기type)/amt`(amt: 전사계 20·레인저/팔라딘 25·도둑/암살/성직 30·마법계 40) → thaco 감소량 겸 **크리티컬 확률(%)**로 재사용(사실상 단자릿수). 무기타입 enum: SHARP0/THRUST1/BLUNT2/POLE3/MISSILE4. **숙련 성장 곡선·전직 테이블 상세는 A7 소관**.

**`compute_ac`**(`player.c:971`) — 방어도(AC), 낮을수록 우수:
```
ac = 100;
ac -= 5 * bonus[MIN(dexterity,63)];      // 민첩이 회피에 직결
for(장비 슬롯) ac -= 장비->armor;         // 착용 AC 합산
if(F_ISSET(ply, PPROTE)) ac -= 10;        // 보호마법
ac = MAX(-127, MIN(127, ac));   ply->armor = ac;
```
명중식은 이 `armor`를 `/8`(플레이어 대상)·`(70-armor)/5`(몬스터 대상)로 스케일한다. 예: AC 100 → 플레이어 대상 명중 임계값 +12.5.

**회피·방어에 별도 굴림은 없다.** 무한은 회피(dodge)·방어(parry/block)를 독립 판정으로 두지 않고 **단일 AC 항 하나로 통합**한다 — 민첩(`5*bonus[dex]`)·착용 장비·보호마법이 전부 `armor` 수치 한 곳에 합산되고, 그 `armor`가 상대 명중식의 임계값을 올려 "덜 맞게" 만드는 것이 방어·회피의 유일한 메커니즘이다(§9의 선공 민첩 회피는 몬스터 *선제타깃팅* 스킵일 뿐 명중 판정이 아니다). 따라서 이식 시 별도 회피 스탯·회피 롤을 만들지 않고 AC 파생만 재현한다.

## 6. 상태이상·환경 피해 틱 (콘텐츠 — DoT 공식)

전투로 걸린 상태이상과 위험 방의 지속 피해는 플레이어 pulse `update_ply`(`player.c:348`, A1이 A7로 이월했으나 **DoT·사망은 A5 소관**, 순수 재생률만 A7)에서 처리된다. `LT_HEALS` 슬롯으로 게이트:

**독(`PPOISN`)** (`player.c:613`): `hpcur -= MAX(1, mrand(1, hpmax/5) - bonus[체력])`, interval `30 - 3*bonus[체력]`초. `hpcur<1`이면 `die(ply, ply)`. → 체력이 피해·주기 양쪽을 완화. 최대 체력의 20%까지 굴리는 강한 DoT.

**질병(`PDISEA`)** (`:630`): `hpcur -= MAX(1, mrand(1,6) - bonus[체력])` + 공격 쿨다운을 `dice(1,6,3)`로 늘림(전투력 저하). `hpcur<1`이면 사망.

**위험 방**(A4가 A5로 이월) (`:642–726`):
| 방 플래그 | 효과 |
|---|---|
| `RPPOIS` | `PPOISN` 부여(방에 있는 한 중독) |
| `RPBEFU` | 혼란 — 공격 쿨다운 `MAX(dice(2,6,0),6)`로 증가 |
| `RPMPDR` | `mpcur -= MIN(mpcur,3)` (마나 흡수) |
| `RPHARM` | 일반 가해 방 — 아래 속성 분기로 |
| 속성 realm `RFIRER`/`RWATER`/`REARTH`/`RWINDR` | 대응 보호(`PRFIRE`/`PBRWAT`/`PSSHLD`/`PRCOLD`) 없으면 `hpcur -= 8 - MIN(bonus[체력],2)` |
| (RPHARM 이면서 위 어느 것도 아님) | "보이지않는 무엇이 생명력을 빨아들입니다" 동일 피해 |

각 사망 판정마다 `hpcur<1`이면 `die`. **재생(healing)은 반대편**: 비-중독·비-가해 방에서 `hpcur += MAX(4, 5+bonus[체력]+(BARBARIAN?2))`, `RHEALR` 방은 +100·주기 1/3 — **재생 수치 자체는 A7 소관**, 여기서는 DoT가 재생과 같은 `LT_HEALS` 슬롯을 공유해 상호 배제된다는 사실만 확정.

## 7. 사망·경험치·전리품 (콘텐츠 — 분배·드롭 규칙)

`die(crt_ptr, att_ptr)`(`creature.c:262`)가 몬스터/플레이어 사망의 단일 진입점(`crt`=죽은 자, `att`=죽인 자). 근접(`command5.c`)·마법(`magic*.c`)·독/함정/방(`player.c`)이 모두 여기로 수렴.

**몬스터 사망** (`creature.c:277–369`):
- **경험치 = 데미지 비례 분배**: 적 리스트(`first_enm`) 순회, 기여자별 `expdiv = 몬스터exp * ep->damage / MAX(hpmax,1)`, 상한 `MIN(expgroup, 몬스터exp)`. `ep->damage`는 타격마다 `add_enm_dmg(name, crt, MIN(hpcur,n))`(오버킬 제외 실데미지)로 누적. 부수: 살해자 `alignment -= 몬스터alignment/5`(±1000 클램프).
- **그룹 보너스 버그**: `if(cp) expgroup = expdiv + 몬스터exp/10`의 `cp`가 **미초기화 지역변수**(`creature.c:268` 선언만) → 보너스 발동이 스택 쓰레기값에 좌우되는 비결정 동작. 원의도(파티킬 보너스 추정)를 **#14에서 결정**해 재현하되 버그는 이식하지 않는다.
- **레벨업은 여기가 아님**: `die`는 exp만 더한다. 실제 레벨 상승은 훈련소 `train`(`command7.c`, `up_level`)에서 골드 내고 수동 수련 — **A7 소관**.
- **시체 없음**: `MTRADE`(상인) 아니면 소지 아이템 전량 `add_obj_rom`으로 방 바닥에 드롭, 골드는 `"{N}냥"`(`value=골드`) objmon 템플릿 idx 0 오브젝트로 드롭. 그 후 `del_active`→`free_crt`로 구조체 해제(corpse 엔티티 미생성). `MPERMT`면 `die_perm_crt`로 리스폰 타이머 갱신(**스폰은 A9**).

**플레이어 사망** (`creature.c:371–526`, 부활 방 하드코딩 **1008**):
| 단계 | 규칙 |
|---|---|
| exp 손실 | level<20: `exp/20`(5%). ≥20: `exp/15>10만`이면 정액 −100000, 아니면 `exp/15`(~6.7%). 2단계 레벨하락 방지 바닥. `MAX(0,exp)` |
| PvP 예외 | 살해자가 플레이어면 **exp 손실 없음**, 대신 살해자에게 `PLYKL` 쿨다운 `mrand(7,14)*86400`초(7~14일) |
| 숙련 손실 | `!RSUVIV && check_war`면 5 proficiency+4 realm 합에서 초과분 가중 차감(최소 1024 보장) |
| 레벨 하락 | `exp_to_lev(exp)`까지 `down_level` 반복 |
| 상태·HP | `hpcur=hpmax`, 독·질병 해제. MP는 PvP 피살 `MAX(mpcur,mpmax/10)`·몬스터 피살 `mpmax` |
| 장비 드롭 | `!RSUVIV && check_war`면 questnum·`ONEWEV`·`OCURSE`·컨테이너 아닌 착용품을 방(PvP)/살해몹(PvE)에 드롭, AC/thaco 재계산 |
| 마무리 | 사망 방송(`!RSUVIV`) → `load_rom(1008)` 부활 → `savegame` 즉시 저장 |
| 골드 | **손실 없음**(코드상 차감 부재). 캐릭터 삭제 아님(영구사망 아님) |

**게임 정체성**: 죽음은 몰수가 아니라 **감쇠**다 — exp·숙련이 깎여 레벨이 내려가고 장비를 흘리지만 골드와 캐릭터는 남고 만HP로 재기한다. PvP는 피해자 손실을 면제하는 대신 살해자에게 장기 쿨다운으로 무분별 PK를 억제한다.

## 8. PvP·안전지대 (콘텐츠 — 3중 게이트)

플레이어가 플레이어를 공격할 때 `attack_crt`의 게이트(`command5.c:167–198`):

1. **안전지대**: 방 `RNOKIL`이면 "이 곳에서는 싸울 수 없습니다" 무조건 거부.
2. **선악 동의 게이트**: 공격자·피격자 어느 쪽이든 `PCHAOS`(카오스/PK 동의) 아니고 `level<128`(필멸자)이고 방이 `RSUVIV`(서바이벌/투기장) 아니면 "당신은 선하다는걸 아세요"/"그 사용자는 선해서 공격할 수 없습니다" 거부. 즉 **양측 다 카오스이거나, 고레벨이거나, RSUVIV 방일 때만** 일반 PK 성립.
3. **패거리 전쟁**: 양측이 `PFAMIL`이면 `check_war(내패거리, 상대패거리)`(`command12.c:430`)로 판정 — 전역 `AT_WAR`(두 교전 패거리를 `AT_WAR/16`·`AT_WAR%16`로 인코딩)에 두 패거리가 맞물리면 **선악 게이트 면제**하고 자유 교전. 그 외엔 선악 게이트 적용.

성립 시 공격 쿨다운 `+3`(PvE보다 느린 PvP 템포). **정렬(alignment) 자체는 이동을 게이트하지 않으며(A4 정정) PvP 허용의 축**이다 — `PCHAOS`가 PK 동의 플래그, `alignment` 수치는 PALADIN 피해 보정(§2)·경험치 획득 이동(§7)에 쓰인다.

## 9. 도주·공격성 (콘텐츠 — 라이브만)

**몬스터 자체 도주(`MFLEER`)는 죽은 코드**: `check_for_flee`(`creature.c:624`)는 함수 두 번째 실행문이 무조건 `return;`이라 이하 도주 로직(`hpcur<=hpmax/5`이면 열린 출구로 `mrand(1,100)<75` 이동)이 **절대 실행되지 않는다**(주석 "10%"와 코드 `/5`=20% 불일치도 존재). → 원본에서 몬스터는 도망치지 않았다. **이식하지 않는다**(A4의 dead 플래그·flag 52 버그와 같은 부류).

**플레이어 도주**(몬스터에게 피격 후, `update.c:534–552`)만 라이브:
- `PWIMPY`: `hpcur <= WIMPYVALUE`면 `flee`(자동 도주).
- `PFEARS`: `ff = 40 + (1 - hpcur/hpmax)*40 + bonus[체력]*3 (+PALADIN -10)`; `ff < mrand(1,100)`이면 `flee`. (정수 나눗셈·삼항 우선순위 버그로 실효 `ff`가 대부분 40 근처 — verbatim이나 이식 시 의도 재현.) `flee`는 `command7.c:19`(A4 §8 이동 게이트 복제 경로).

**몬스터 선공(aggro)**(`update.c:587–615`), 적 없을 때 타깃 자동 선정:
| 플래그 | 타깃 선정 |
|---|---|
| `MAGGRE`(무차별) | `lowest_piety` — 신앙심 최저 플레이어 |
| `MGAGGR`(선인 대상) | `low_piety_alg(…, -1, …)` |
| `MEAGGR`(악인 대상) | `low_piety_alg(…, +1, …)` |
| `MDINVI` | 은신 플레이어 탐지 여부 |

**민첩 회피**: `att->dexterity > crt->dexterity && mrand(1,10) < 4`면 이번 라운드 선공 스킵(민첩 높은 플레이어 30% 선제 회피). 성공 시 공격 메시지 + `LT_ATTCK.interval=0`(즉시 다음 틱 공격) + `add_enm_crt`로 적대 등록 → **다음 틱부터 §3 경로로 실타격**. 즉 선공은 "이번 틱 접촉 → 다음 틱 타격"의 2단이다.

## 아키텍처 함의 (이슈 #14 입력)

**전투 엔진은 A1 매초 활성 리스트 순회 위에 얹는다.** 원본의 몬스터 구동 틱(각 몬스터 2~3초 쿨다운, 플레이어는 오프너+반격)이 공격 빈도·반격 타이밍이라는 밸런스를 정의하므로, 엔티티마다 `setTimeout`을 남발하지 않고 **A1 권장대로 매초 활성 크리처를 순회하며 "다음 가용 시각"(`LT_ATTCK` 대응 필드)을 비교**하는 결정적 모델로 재현한다. 4중으로 복제된 게이트·피해 코드(플레이어 `attack_crt` / 몬스터 인라인)는 **단일 `resolveAttack(attacker, defender, ctx)` 파이프라인**으로 통합하되, 플레이어/몬스터 스케일 차이(`mrand(1,30)`vs`(1,20)`, 피해식, 크리티컬 유무)는 mode 파라미터로 분기한다.

**thaco 비대칭을 스키마에 반영한다.** 몬스터 thaco/armor/dice는 **템플릿에 저장된 저작 데이터**(이식 시 그대로 로드), 플레이어 thaco/armor는 **런타임 계산 파생값**(`compute_thaco`/`compute_ac`를 장비·레벨·능력치 변경마다 재실행). 즉 몬스터는 "읽는다", 플레이어는 "계산한다" — 저장 모델에서 몬스터 전투 스탯은 불변 템플릿, 플레이어 전투 스탯은 파생 캐시로 설계한다.

**공식은 상수 테이블로 외부화한다.** `bonus[64]`·`thaco_list[13][20]`·`prof_array[클래스][12]`·주사위 파라미터·특수공격 확률(13%/10%/15%…)·사망 손실률(5%/6.7%/10만)은 전부 데이터로 분리해 **밸런스 튜닝이 코드 수정 없이 가능**하게 한다(원본은 `global.c` 하드코딩). 이는 이슈 목표 "밸런스 유지"에 직결된다.

**결정 필요(#14)**: ① 전투 모델을 몬스터 구동(원본 충실)으로 갈지 플레이어 독립 공격 루프를 추가할지(현 판단: 몬스터 구동 재현). ② `cp` 미초기화 그룹킬 보너스의 원의도 — 파티/그룹 데미지 기여 시 `+exp/10`을 결정적으로 적용할지(권장) 폐기할지. ③ `PHASTE` 가속 무효·`PBLESS` thaco 미반영 등 버그성 dead를 의도대로 살릴지(가속이 실제로 공격 속도를 올리게) 원본대로 무효로 둘지. ④ 사망 부활 방 `1008` 하드코딩을 설정/종족별 부활지로 확장할지.
