# A5 전투 시스템

> 무한의 전투 공식(명중·피해·크리티컬·사망·경험치)과 전투 라운드가 *어떻게 진행되는지*를 오라클에서 정리한다. 목적은 밸런스 유지이므로, 공식과 수치는 충실히 이식하고 구현은 자유롭게 재설계한다. 이슈 #5. 출처는 `legacy/muhan/src`(EUC-KR, byte-level)와 변환 산출물 `data/world/creatures.json`(몬스터 템플릿 672)이며, 코드를 이식하지 않고 동작만 추출한다.
>
> **빌드 원본 파일 정정(선결)**: 이슈는 전투 코드로 `comman5_old.c`(`attack`)를 지목했다. 그러나 **실제로 컴파일·링크되는 파일은 `command5.c`**다. 근거는 두 가지다.
> - (a) `command5.o`(61988B)는 있고 `comman5_old.o`는 없다.
> - (b) `util/MAKEFILE:6` `.o` 파일 링크 목록에 `command5.o`가 있고, `comman5_old`는 어디에도 없다.
>
> 두 파일의 `attack_crt`는 두 곳만 다르다.
> - ① 명중식이 `armor/10`(구)에서 **`armor/8`**(빌드본, `command5.c:231`)로 바뀌었다.
> - ② 인라인 HP 상태바 출력이 `display_status()` 호출로 리팩터링됐다.
>
> 피해, 크리티컬, 불발, 내구도 로직은 바이트까지 같다. 이 노트의 모든 라인 번호와 공식은 `command5.c` 빌드본을 기준으로 한다. `comman5_old.c`는 A4가 기록한 dead 플래그나 죽은 코드처럼 디스크에는 있지만 엔진이 읽지 않는 파일로 보고 이식하지 않는다.

## 개요

무한의 전투는 **몬스터 틱 기반 라운드**로 진행된다. 플레이어의 `attack` 명령은 전투를 *시작*하기만 한다. 1회 타격하고 적대 관계를 등록하는 것이 전부다. 이후 라운드는 중앙 1Hz 틱의 `update_active`(A1)가 진행한다. 이 함수는 활성 몬스터 리스트를 매초 순회하면서, 각 몬스터가 자기 쿨다운(민첩에 따라 2~3초)마다 공격하게 한다. 그러면 그 몬스터의 적 리스트에 있는 플레이어들이 **자동으로 반격**(`attack_crt`)한다. 플레이어 쪽에는 독립된 "초당 공격 스케줄러"가 없다. 첫 공격 이후 플레이어가 주는 피해는 모두 몬스터 틱 안에서 처리되는 반격이다.

명중 판정은 D&D THAC0 방식이다. **난수 굴림이 `thaco - armor/8` 임계값을 넘으면 명중**하며, thaco와 armor가 낮을수록 유리하다. 플레이어와 몬스터는 같은 구조를 쓰되 스케일이 다르다.
- 플레이어: `mrand(1,30)`으로 굴리고, 피해는 무기 주사위 + 힘 보너스 + 숙련이다.
- 몬스터: `mrand(1,20)`으로 굴리고, 피해는 자기 주사위 − 방어 경감이다.

중요한 비대칭이 하나 있다. 플레이어 thaco는 클래스, 레벨, 장비로 *계산*(`compute_thaco`)하는 파생값이다. 반면 **몬스터 thaco는 템플릿에 *저장된 저작 데이터***다(실측 중앙값 5).

핵심 분리:
- **콘텐츠(충실히 이식):** 공식, 수치, 라운드 주기, 게이트 의미.
- **구현 방식(재설계):** 연결 리스트 순회, 인라인 4중 복제, 초 단위 폴링, 미초기화 변수 버그.

## 1. 전투 루프 구조 = 몬스터 틱 기반 + 플레이어 반격 (콘텐츠)

이슈가 "라운드 진행"으로 지목한 부분이며, 모든 공식이 이 흐름 안에서 호출된다. **플레이어에게는 능동 스케줄러가 없다.** 전체 소스를 grep해 보면 `attack_crt(player, monster)`가 실행되는 경로는 두 곳뿐이다.

| 호출부 | 주체 | 성격 |
|---|---|---|
| `command5.c:89` (`attack` 명령) | 플레이어 | **오프너 1회** — 한 번 때리고 `add_enm_crt`로 적대 등록 |
| `update.c:512, 517, 569, 574` | 플레이어(반격) | 몬스터 틱 내부에서 그 몬스터의 적 리스트 플레이어들이 자동 반격 |

즉 라운드 진행의 기준은 `update.c`의 **`update_active(t)`**(`update.c:229`)다. A1이 "매초 전투 진행"으로 넘긴 함수다. 이 함수는 매초 `first_active`(활성 몬스터 `ctag` 연결 리스트)를 순회하며 몬스터마다 다음을 처리한다.

| 순서 | 단계 | 조건/효과 | 출처 |
|---|---|---|---|
| 1 | 방 정리 | 방에 플레이어 없으면(`!first_ply`) `del_active` 후 스킵 | update.c:254 |
| 2 | 혼란 해제 | `LT(crt,LT_BEFUD)<t`면 `MBEFUD` 해제 | :259 |
| 3 | 자가 회복 | `LT_HEALS` 만료마다 `hpcur += MAX(1,hpmax/10)`, `mpcur += MAX(1,mpmax/6)`, **interval 60초** | :264 |
| 4 | 매혹 해제 | `LT_CHRMD` 만료 시 `MCHARM` 해제 | :277 |
| 5 | **공격 쿨다운 게이트** | `LT(crt,LT_ATTCK)>t`면 이번 몬스터 스킵 | :280 |
| 6 | 쿨다운 재설정 | `interval = (dexterity<20) ? 3 : 2` — **민첩<20이면 3초, 이상이면 2초 주기** | :285 |
| 7 | 스캐빈저 | `MSCAVE` + 20초 경과 + `mrand(1,100)<=15`면 방 바닥 아이템 줍기(`MHASSC` 설정) | :291 |
| 8 | 방황 despawn | 비-`MHASSC`·비-`MPERMT`·비-`MDMFOL` + 20초 + `mrand(1,100)<=traffic` + 적 없음이면 방 떠나 `free_crt` | :312 |
| 9 | 비전투 종료 | 적 없고 `MAGGRE`/`MGAGGR`/`MEAGGR` 전부 없으면 무행동 | :329 |
| — | (A) 적 있음 | `first_enm` → §3 공격 실행 | :334 |
| — | (B) 선공 | 공격성 플래그로 신규 타깃 선정 → §9 | :587 |

**라운드 주기는 몬스터의 2~3초 틱**이며, 플레이어 공격 주기가 아니다. 플레이어가 첫 공격 1타를 한 뒤에는 몬스터가 자기 틱에 공격하고, 같은 틱 안에서 적 리스트의 플레이어들이 `attack_crt`로 반격한다(`update.c:502–523`·`560–580`, `NUMHITS≠0`일 때). 반격도 `attack_crt` 시작 부분에서 플레이어의 `LT_ATTCK` 쿨다운을 다시 검사한다. 따라서 플레이어가 실제로 때리는 빈도는 몬스터 틱과 자기 쿨다운이 모두 맞을 때로 정해진다.

> **#14 결정 포인트**: 신규 스택에서 전투를 어떻게 진행할지 정해야 한다. (a) 원본대로 **몬스터 기반 틱 + 플레이어 반격**으로 재현하거나, (b) 플레이어에게도 독립 공격 루프를 준다. 현재 판단: 원본의 몬스터 기반 모델이 밸런스(공격 빈도, 반격 타이밍)를 정하므로 **A1의 매초 활성 리스트 순회를 그대로 써서 재현**한다. 다만 4중 인라인 복제(§) 코드는 통합한다.

## 2. 플레이어 근접 공격 = `attack_crt` (빌드본 `command5.c`) (콘텐츠)

플레이어 `attack` 명령(`command5.c:36`)은 시작할 때 다음을 검사한다.
- `class==0`(전투금지 직업)이면 거부한다.
- `LT_ATTCK` 쿨다운이 끝날 때까지 기다린다.
- `cmnd->num<2` 또는 `PBLIND`면 대상이 지정되지 않은 것으로 보고 거부한다.
- `ply_is_attacking`(이미 교전 중)이면 거부한다.
- `find_crt`로 방에서 몬스터, 플레이어 순으로 대상을 찾는다.

모두 통과하면 **`attack_crt(ply_ptr, crt_ptr)`를 1회 호출**한다(`command5.c:89`).

`attack_crt`(`command5.c:103`) 본문은 다음 순서로 진행된다.

**쿨다운 설정** (`:131–138`): `lasttime[LT_ATTCK].ltime=t`로 설정한다. `interval=1`은 무기와 맨손에 공통이다. `PHASTE` 분기도 양쪽 모두 `1`이라 **가속이 효과가 없는 버그**가 있다. `PBLIND`면 `interval=6`이다. PvP(대상이 플레이어)면 뒤에서 `interval += 3`을 더한다.

**대상 무적 플래그** (`:139–166`, 몬스터 한정): `MUNKIL`(해칠 수 없음)이면 거부한다. `MMGONL`(마법무기만)이면 거부한다. `MENONL`(마법무기 필요)이고 플레이어 무기가 `adjustment<1`이면 거부한다.

**PvP 게이트** (`:167–198`, 대상이 플레이어): §8 참조.

**다중 공격** (`:200–209`): 초인 전용 연타다.
- `PUPDMG`를 가지고 있고 `(INVINCIBLE·level>100)‖class>INVINCIBLE`이면, `(level-97)/10 + mrand(0,3) > 2`일 때 `count++`.
- `class>INVINCIBLE`이고 `mrand(1,4)==1`이면 `count++`를 한 번 더 한다.

`for(count)` 루프 안에서 타격마다 다음을 처리한다.

**명중** (`command5.c:231–236`):
```
n = ply_ptr->thaco - crt_ptr->armor/8;     // 빌드본: /8 (구 백업은 /10)
if(F_ISSET(ply, PFEARS)) n += 2;
if(F_ISSET(ply, PBLIND)) n += 5;
if(mrand(1,30) >= n) { …명중… }            // 주석 "원래값 20" — d20→d30 완화
```

**피해** (`:237–259`), 클래스·장비별 분기:

| 조건 | 피해식 |
|---|---|
| 무기 장착 | `mdice(무기) + bonus[힘] + profic(ply, 무기type)/10` (+ 오프핸드 비-방어구면 `+ mdice(HELD)/10`) |
| BARBARIAN 또는 class>INVINCIBLE | `mdice(자기) + bonus[힘] + (level+3)/4` |
| 그 외 맨손 | `mdice(자기) + bonus[힘]` |
| MAGE/CLERIC | 무기 있으면 `mdice(무기)+bonus[힘]`, 없으면 `mdice(자기)+bonus[힘]` |
| 대상 class≥DM | `n = 0` (DM 무적) |

그다음 `n = MAX(1,n)`을 적용한다. **PALADIN 성향 보정**(`:261–270`): `alignment<0`이면 `n/=2`(악행 페널티), `alignment>250`이면 `n += mrand(1,3)`(선행 보너스)이다.

**크리티컬·불발** (`:272–306`): `p = mod_profic(ply)`(§4)이며, 값은 대략 0~5다.
- 크리티컬: `mrand(1,100) <= p`이거나 무기에 `OALCRT` 플래그가 있으면 초록색 "치명타"를 출력하고 `n *= mrand(3,6)`(3~6배)을 적용한다.
  - 크리티컬이 나면 무기가 부서질 수 있다. `ONSHAT`가 아니고 `mrand(1,100)<3`이거나 `OALCRT`이면서, `ONEWEV`가 아니면 `free_obj`한다.
- 불발: `mrand(1,100) <= (5-p)`이고, 무기가 있으며 `OCURSE`가 아니면 무기를 떨어뜨린다. `n=0`이 되고 `compute_thaco`를 다시 계산한다.

**적용** (`:308–374`):
- 데미지 메시지와 `display_status`(HP 바)를 출력한다.
- 무기 내구도: `!mrand(0,3)`(25%)이면 `shotscur--`.
- `crt->hpcur -= n`을 적용한다.
- 대상이 몬스터면 `add_enm_dmg`로 기여 피해를 누적하고, 무기 숙련 `addprof = MIN(m*experience/MAX(hpmax,1), experience)`를 얻는다.
- `hpcur<1`이면 `die(crt, ply)`(§7) 후 `return(1)`한다. 아니면 `check_for_flee`(죽은 코드, §13)를 호출한다.
- 빗나가면 "허공을 쳤습니다"를 출력한다.

**실측 근거**(data/world 몬스터 672): thaco는 중앙값 5, p90 18(min −30 max 100)이다. armor는 중앙값 0, p90 90(min −127 max 127)이다. 따라서 저레벨 몬스터에서 명중 임계값 `thaco − armor/8`은 대체로 한 자릿수라 `mrand(1,30)`이 쉽게 넘는다. 즉 대부분의 전투에서는 기본적으로 명중하고, armor가 높은 방어형 몬스터에서만 회피가 의미 있어진다.

## 3. 몬스터 근접 공격 = `update_active` 인라인 (콘텐츠)

몬스터는 `attack_crt`를 쓰지 않고, `update_active` 안의 **자체 인라인 로직**으로 공격한다(`update.c:334–585`). 타깃은 `first_enm->enemy`를 `find_crt`로 찾는다.

**주문 분기** (`:348–376`, `MMAGIC`):
- 시전 확률은 `n=20`이고, `MMAGIO`면 `proficiency[0]`을 쓴다.
- `mrand(1,100)<=n`이고 매혹 상태가 아니면 `crt_spell`(`update.c:654`)을 호출한다. 이 함수는 아는 주문 중 하나를 `mrand`로 고르고, offensive 주문이면 `offensive_spell`을 쓴다.
- 반환값이 2면 라운드를 다시 시작하고, 1이면 근접 공격을 건너뛴다(그 라운드에는 주문이 공격이다). 0이면 근접 공격을 진행한다.

**마법 데미지 공식 자체는 A6 담당**이다.

**명중** (`:373–383`):
```
n = crt_ptr->thaco - att_ptr->armor/8;
n = MAX(n, 1);
if(mrand(1,20) >= n) { …명중… }            // 플레이어보다 좁은 d20 굴림
```

**피해** (`:439–447`):
```
n = mdice(crt_ptr) - ((70 - att_ptr->armor)/5);   // armor 다른 스케일(70기준,/5)
if(n < 1) n = 1;
if(F_ISSET(crt, MBEFUD)) n = n/3;                 // 혼란 몬스터 1/3
att_ptr->hpcur -= n;
```

**플레이어 vs 몬스터 근접 대조**:

| 항목 | 플레이어 (`command5.c`) | 몬스터 (`update.c`) |
|---|---|---|
| 명중식 | `thaco − armor/8` | `thaco − armor/8` (동일) |
| 명중 굴림 | `mrand(1,30) >= n` | `mrand(1,20) >= n` (더 좁음 = 몬스터 명중률 높음) |
| 피해 | `mdice(무기/자기) + bonus[힘] + profic/10` | `mdice(자기) − (70−armor)/5` |
| 크리티컬 | 있음(`mod_profic`) | 없음(브레스/특수공격으로 대체) |
| 쿨다운 | `LT_ATTCK` interval 1(PvP +3, 실명 6) | interval 2(dex≥20)/3(dex<20) |
| thaco 출처 | **계산**(`compute_thaco`) | **저장 데이터**(템플릿) |

피해 실측(몬스터 672): 중앙값은 `ndice` 4, `sdice` 5, `pdice` 2다. 따라서 전형적인 몬스터의 피해는 ≈ `4d5+2`(평균 ~14)다. 다만 보스급은 `sdice`가 최대 492, `pdice`가 최대 5700으로 극단적이다. `experience`는 최대 666666이다.

## 4. 명중·방어 스택 (콘텐츠 — 테이블·공식)

명중과 피해 계산에 쓰이는 보조 함수와 테이블이다. **주사위·보너스 테이블이 전투 밸런스를 결정**하므로 값 전체를 이식한다.

**`dice(n,s,p)`**(`misc.c:454`) + 매크로 `mdice(a)=dice(a->ndice,a->sdice,a->pdice)`(`mtype.h:588`):
```
for(i=0;i<n;i++) p += mrand(1,s);   return p;    // p + n개의 s면체 합
```
**`mrand(a,b)`**(`mtype.h:587`): `[a,b]` **양끝 포함 정수 균등**.

**`bonus[64]`**(`global.c:57`) — 능력치(힘·민첩·신앙 등) 인덱싱, 값 −4~+7:
```
idx  0- 7:  -4 -4 -4 -3 -3 -2 -2 -1
idx  8-15:  -1 -1  0  0  0  0  1  1
idx 16-23:   1  2  2  2  3  3  3  3
idx 24-31:   4  4  4  4  4  5  5  5
idx 32-39:   5  5  5  6  6  6  6  6
idx 40-47:   6  6  6  6  7  7  7  7
idx 48-63:   7 (이하 전부 7)
```

**`compute_thaco`**(`player.c:1001`) — 플레이어 thaco 산출(파생값):
```
col = MIN(19, (level+3)/4 - 1);
thaco = thaco_list[class][col];
thaco -= 무기->adjustment;
thaco -= mod_profic(ply);
thaco -= bonus[strength];
thaco = MAX(하한, thaco);   // class<CARETAKER: level<101 → 0, 그 이상 → -5; DM계열 → -10
// (PBLESS -3은 대입 후라 미반영 = dead)
```
`thaco_list[13][20]`(`global.c:94`)은 행이 클래스 enum, 열이 `(level+3)/4−1`이다. 발췌:
- FIGHTER(4): `20,19,18,…,4,3,3,3`(레벨이 오를수록 낮아짐)
- MAGE(5): `20,20,19,…,13,13,11`(완만하게 낮아짐)
- INVINCIBLE(9): 전부 1
- CARETAKER/SUB_DM/DM(10~12): 전부 −5

값이 낮을수록 명중이 쉬우므로, 전사 계열이 가장 유리하고 마법사 계열이 가장 불리하다.

**`profic`/`mod_profic`**(`player.c:1120`/`1032`) — 무기 숙련.
- `profic`은 `proficiency[무기type]` 경험치가 클래스별 임계 테이블 `prof_array[12]`의 어느 구간에 있는지 보고, 0~약110%를 선형보간해 반환한다. 피해에는 `/10`해서 더하므로 구간당 +1이다.
- `mod_profic`은 `profic(장착무기type)/amt`다(amt: 전사계 20·레인저/팔라딘 25·도둑/암살/성직 30·마법계 40). 이 값은 thaco 감소량으로 쓰이고, **크리티컬 확률(%)**로도 다시 쓰인다(사실상 한 자릿수).
- 무기타입 enum: SHARP0/THRUST1/BLUNT2/POLE3/MISSILE4.

**숙련 성장 곡선과 전직 테이블 상세는 A7 담당**이다.

**`compute_ac`**(`player.c:971`) — 방어도(AC), 낮을수록 우수:
```
ac = 100;
ac -= 5 * bonus[MIN(dexterity,63)];      // 민첩이 회피에 직결
for(장비 슬롯) ac -= 장비->armor;         // 착용 AC 합산
if(F_ISSET(ply, PPROTE)) ac -= 10;        // 보호마법
ac = MAX(-127, MIN(127, ac));   ply->armor = ac;
```
명중식은 이 `armor`를 `/8`(플레이어 대상) 또는 `(70-armor)/5`(몬스터 대상)로 스케일한다. 예: AC 100이면 플레이어 대상 명중 임계값이 +12.5다.

**회피·방어에 별도 굴림은 없다.** 무한은 회피(dodge)와 방어(parry/block)를 따로 판정하지 않고 **AC 항 하나로 통합**한다. 민첩(`5*bonus[dex]`), 착용 장비, 보호마법이 모두 `armor` 수치 하나에 합산된다. 이 `armor`가 상대 명중식의 임계값을 올려 "덜 맞게" 하는 것이 방어와 회피의 유일한 메커니즘이다. §9의 선공 민첩 회피는 몬스터가 *먼저 타깃으로 삼는 것*을 건너뛰는 것일 뿐 명중 판정이 아니다. 따라서 이식할 때 별도 회피 스탯이나 회피 굴림을 만들지 않고 AC 파생값만 재현한다.

## 5. 몬스터 특수공격 (콘텐츠 — 플래그·확률)

모두 확률로 발동하는 6종이며, 전부 `update_active`의 근접 분기 안에 있다.

| 특수공격 | 플래그 | 발동 조건 | 효과 |
|---|---|---|---|
| **브레스 무기** | `MBRETH` | `mrand(1,30)<5` (≈13%) | `MBRWP1/2` 2비트로 4타입: 침(`dice((lv+3)/4,3,0)`)·악취입김(`dice(..,2,1)`+`PPOISN`)·냉기(`PRCOLD`저항 시 반감)·화염(`PRFIRE`저항 시 반감) |

| **중독** | `MPOISS` | 명중 후 `mrand(1,100)<=15` | `PPOISN` 설정(§6 독 DoT로 이어짐) |
| **질병** | `MDISEA` | 명중 후 `mrand(1,100)<=10` | `PDISEA` 설정 |
| **실명** | `MBLNDR` | 명중 후 `mrand(1,100)<=10` | `PBLIND` 설정(명중·공격속도 페널티) |
| **장비 용해** | `MDISIT` | 명중 후 `mrand(1,100)<=15` | `dissolve_item` — 착용 슬롯 랜덤 1개 `ONEWEV` 아니면 소멸 |

명중 직후에는 방어구도 마모된다. `choose_item`으로 착용 방어구 1개를 골라 `shotscur--`하고, 0 미만이면 파괴한다. 브레스와 드레인의 주사위 개수는 `(level+3)/4`로, 레벨에 따라 늘어난다. **몬스터가 플레이어 아이템을 훔치는(steal) 공격은 없다.** `steal`(`command6.c:723`)은 도둑 클래스 전용 명령이다. 몬스터 동작 중 가장 비슷한 것은 §1-7의 `MSCAVE`인데, 이는 바닥 아이템을 줍는 것이지 인벤토리를 훔치는 것이 아니다.

## 6. 상태이상·환경 피해 틱 (콘텐츠 — DoT 공식)

전투로 걸린 상태이상과 위험 방의 지속 피해는 플레이어 pulse `update_ply`(`player.c:348`)에서 처리된다. A1은 이 함수를 A7로 넘겼지만, **DoT와 사망은 A5 담당**이고 순수 재생률만 A7이 맡는다. 처리 시점은 `LT_HEALS` 슬롯으로 제어한다.

**독(`PPOISN`)** (`player.c:613`): `hpcur -= MAX(1, mrand(1, hpmax/5) - bonus[체력])`이고, interval은 `30 - 3*bonus[체력]`초다. `hpcur<1`이면 `die(ply, ply)`. → 체력이 높으면 피해와 주기 양쪽이 완화된다. 최대 체력의 20%까지 굴리는 강한 DoT다.

**질병(`PDISEA`)** (`:630`): `hpcur -= MAX(1, mrand(1,6) - bonus[체력])`를 적용하고, 공격 쿨다운을 `dice(1,6,3)`로 늘린다(전투력 저하). `hpcur<1`이면 사망한다.

**위험 방**(A4가 A5로 넘김) (`:642–726`):
| 방 플래그 | 효과 |
|---|---|
| `RPPOIS` | `PPOISN` 부여(방에 있는 한 중독) |
| `RPBEFU` | 혼란 — 공격 쿨다운 `MAX(dice(2,6,0),6)`로 증가 |
| `RPMPDR` | `mpcur -= MIN(mpcur,3)` (마나 흡수) |
| `RPHARM` | 일반 가해 방 — 아래 속성 분기로 |
| 속성 realm `RFIRER`/`RWATER`/`REARTH`/`RWINDR` | 대응 보호(`PRFIRE`/`PBRWAT`/`PSSHLD`/`PRCOLD`) 없으면 `hpcur -= 8 - MIN(bonus[체력],2)` |
| (RPHARM 이면서 위 어느 것도 아님) | "보이지않는 무엇이 생명력을 빨아들입니다" 동일 피해 |

사망 판정마다 `hpcur<1`이면 `die`를 호출한다. **재생(healing)은 반대 방향의 처리다.** 중독되지 않았고 가해 방이 아니면 `hpcur += MAX(4, 5+bonus[체력]+(BARBARIAN?2))`만큼 회복한다. `RHEALR` 방에서는 +100이고 주기는 1/3이다. **재생 수치 자체는 A7 담당**이다. 여기서는 DoT와 재생이 같은 `LT_HEALS` 슬롯을 공유해 서로 배타적으로 동작한다는 사실만 확정한다.

## 7. 사망·경험치·전리품 (콘텐츠 — 분배·드롭 규칙)

`die(crt_ptr, att_ptr)`(`creature.c:262`)는 몬스터와 플레이어 사망을 모두 처리하는 단일 진입점이다(`crt`=죽은 자, `att`=죽인 자). 근접(`command5.c`), 마법(`magic*.c`), 독/함정/방(`player.c`)에 의한 사망이 모두 이 함수를 거친다.

**몬스터 사망** (`creature.c:277–369`):
- **경험치 = 데미지 비례 분배**: 적 리스트(`first_enm`)를 순회하며 기여자별로 `expdiv = 몬스터exp * ep->damage / MAX(hpmax,1)`를 준다. 상한은 `MIN(expgroup, 몬스터exp)`다.
  - `ep->damage`는 타격마다 `add_enm_dmg(name, crt, MIN(hpcur,n))`로 누적된다. 오버킬을 뺀 실제 데미지다.
  - 부수 효과로 살해자에게 `alignment -= 몬스터alignment/5`를 적용한다(±1000 클램프).
- **그룹 보너스 버그**: `if(cp) expgroup = expdiv + 몬스터exp/10`의 `cp`가 **미초기화 지역변수**다(`creature.c:268`에 선언만 있다). 그래서 보너스가 발동할지가 스택의 쓰레기값에 달린 비결정 동작이 된다. 원래 의도(파티 킬 보너스로 추정)는 **#14에서 결정**해 재현하고, 버그는 이식하지 않는다.
- **레벨업은 여기서 일어나지 않는다**: `die`는 exp만 더한다. 실제 레벨 상승은 훈련소 `train`(`command7.c`, `up_level`)에서 골드를 내고 직접 수련해야 한다. **A7 담당**이다.
- **시체 없음**: `MTRADE`(상인)가 아니면 소지 아이템을 전부 `add_obj_rom`으로 방 바닥에 떨어뜨린다.
  - 골드는 `"{N}냥"`(`value=골드`)이라는 objmon 템플릿 idx 0 아이템으로 떨어뜨린다.
  - 그 후 `del_active`→`free_crt`로 구조체를 해제한다. corpse 엔티티는 만들지 않는다.
  - `MPERMT`면 `die_perm_crt`로 리스폰 타이머를 갱신한다(**스폰은 A9**).

**플레이어 사망** (`creature.c:371–526`, 부활 방 하드코딩 **1008**):
| 단계 | 규칙 |
|---|---|
| exp 손실 | level<20: `exp/20`(5%). ≥20: `exp/15>10만`이면 정액 −100000, 아니면 `exp/15`(~6.7%). 2단계 레벨하락 방지 바닥. `MAX(0,exp)` |
| PvP 예외 | 살해자가 플레이어면 **exp 손실 없음**, 대신 살해자에게 `PLYKL` 쿨다운 `mrand(7,14)*86400`초(7~14일) |
| 숙련 손실 | `!RSUVIV && check_war`면 5 proficiency+4 realm 합에서 초과분 가중 차감(최소 1024 보장) |
| 레벨 하락 | `exp_to_lev(exp)`까지 `down_level` 반복 |
| 상태·HP | `hpcur=hpmax`, 독·질병 해제. MP는 PvP 피살 `MAX(mpcur,mpmax/10)`·몬스터 피살 `mpmax` |
| 장비 드롭 | `!RSUVIV && check_war`면 questnum·`ONEWEV`·`OCURSE`·컨테이너 아닌 착용품을 방(PvP)/살해 몬스터(PvE)에 드롭, AC/thaco 재계산 |
| 마무리 | 사망 방송(`!RSUVIV`) → `load_rom(1008)` 부활 → `savegame` 즉시 저장 |
| 골드 | **손실 없음**(코드상 차감 없음). 캐릭터 삭제 아님(영구사망 아님) |

**게임 정체성**: 죽음은 모든 것을 빼앗는 것이 아니라 **조금씩 깎는 것**이다. exp와 숙련이 깎여 레벨이 내려가고 장비를 떨어뜨리지만, 골드와 캐릭터는 남고 HP가 가득 찬 상태로 다시 시작한다. PvP에서는 피해자의 손실을 면제하는 대신, 살해자에게 긴 쿨다운을 걸어 무분별한 PK를 막는다.

## 8. PvP·안전지대 (콘텐츠 — 3중 게이트)

플레이어가 플레이어를 공격할 때 `attack_crt`는 다음 게이트를 검사한다(`command5.c:167–198`).

1. **안전지대**: 방이 `RNOKIL`이면 "이 곳에서는 싸울 수 없습니다"를 출력하고 무조건 거부한다.
2. **선악 동의 게이트**: 다음 조건이 모두 맞으면 "당신은 선하다는걸 아세요"/"그 사용자는 선해서 공격할 수 없습니다"를 출력하고 거부한다.
   - 공격자나 피격자 중 한쪽이 `PCHAOS`(카오스/PK 동의)가 아니다.
   - `level<128`(필멸자)이다.
   - 방이 `RSUVIV`(서바이벌/투기장)가 아니다.

   즉 일반 PK는 **양측이 모두 카오스이거나, 고레벨이거나, RSUVIV 방일 때만** 가능하다.
3. **패거리 전쟁**: 양측이 모두 `PFAMIL`이면 `check_war(내패거리, 상대패거리)`(`command12.c:430`)로 판정한다. 전역 `AT_WAR`는 교전 중인 두 패거리를 `AT_WAR/16`·`AT_WAR%16`로 인코딩한다. 두 패거리가 여기에 해당하면 **선악 게이트를 면제**하고 자유롭게 교전할 수 있다. 그 외에는 선악 게이트를 적용한다.

PvP가 성립하면 공격 쿨다운에 `+3`이 붙어 PvE보다 템포가 느리다. **성향(alignment)은 이동을 막지 않지만(A4 정정) PvP 허용 여부를 가르는 기준**이다. `PCHAOS`가 PK 동의 플래그이고, `alignment` 수치는 PALADIN 피해 보정(§2)과 경험치 획득 시 성향 변화(§7)에 쓰인다.

## 9. 도주·공격성 (콘텐츠 — 라이브만)

**몬스터 자체 도주(`MFLEER`)는 죽은 코드**다. `check_for_flee`(`creature.c:624`)는 두 번째 실행문이 무조건 `return;`이다. 그래서 그 아래의 도주 로직은 **절대 실행되지 않는다**. 이 로직은 `hpcur<=hpmax/5`이면 `mrand(1,100)<75` 확률로 열린 출구로 이동하는 내용이다. 주석은 "10%"인데 코드는 `/5`=20%라서 서로 맞지도 않는다. → 원본에서 몬스터는 도망치지 않았다. A4의 dead 플래그나 flag 52 버그와 같은 경우이므로 **이식하지 않는다**.

**플레이어 도주**(몬스터에게 맞은 뒤, `update.c:534–552`)만 라이브에서 동작한다.
- `PWIMPY`: `hpcur <= WIMPYVALUE`면 `flee`(자동 도주).
- `PFEARS`: `ff = 40 + (1 - hpcur/hpmax)*40 + bonus[체력]*3 (+PALADIN -10)`이고, `ff < mrand(1,100)`이면 `flee`한다.
  - 정수 나눗셈과 삼항 연산자 우선순위 버그 때문에 실제 `ff`는 대부분 40 근처다. 코드는 원문 그대로 옮겼지만, 이식할 때는 의도한 동작을 재현한다.
  - `flee`는 `command7.c:19`에 있다(A4 §8의 이동 게이트 복제 경로).

**몬스터 선공(aggro)**(`update.c:587–615`): 적이 없을 때 타깃을 자동으로 고른다.
| 플래그 | 타깃 선정 |
|---|---|
| `MAGGRE`(무차별) | `lowest_piety` — 신앙심 최저 플레이어 |
| `MGAGGR`(선인 대상) | `low_piety_alg(…, -1, …)` |
| `MEAGGR`(악인 대상) | `low_piety_alg(…, +1, …)` |
| `MDINVI` | 은신 플레이어 탐지 여부 |

**민첩 회피**: `att->dexterity > crt->dexterity && mrand(1,10) < 4`면 이번 라운드의 선공을 건너뛴다. 즉 민첩이 높은 플레이어는 30% 확률로 선공을 피한다. 선공이 성공하면 공격 메시지를 출력하고, `LT_ATTCK.interval=0`으로 바로 다음 틱에 공격하게 하며, `add_enm_crt`로 적대 관계를 등록한다. → **다음 틱부터 §3 경로로 실제 타격**이 들어간다. 즉 선공은 "이번 틱에 접촉 → 다음 틱에 타격"의 2단계다.

## 아키텍처 시사점 (이슈 #14 입력)

**전투 엔진은 A1의 매초 활성 리스트 순회를 그대로 쓴다.** 원본의 몬스터 기반 틱(각 몬스터 2~3초 쿨다운, 플레이어는 첫 공격 + 반격)이 공격 빈도와 반격 타이밍이라는 밸런스를 정한다. 따라서 엔티티마다 `setTimeout`을 남발하지 않는다. 대신 **A1 권장대로 매초 활성 몬스터를 순회하며 "다음 가용 시각"(`LT_ATTCK`에 대응하는 필드)을 비교**하는 결정적 모델로 재현한다. 4중으로 복제된 게이트·피해 코드(플레이어 `attack_crt` / 몬스터 인라인)는 **단일 `resolveAttack(attacker, defender, ctx)` 파이프라인**으로 통합한다. 플레이어와 몬스터의 스케일 차이(`mrand(1,30)`vs`(1,20)`, 피해식, 크리티컬 유무)는 mode 파라미터로 분기한다.

**thaco 비대칭을 스키마에 반영한다.**
- 몬스터 thaco/armor/dice는 **템플릿에 저장된 저작 데이터**다. 이식할 때 그대로 로드한다.
- 플레이어 thaco/armor는 **런타임에 계산하는 파생값**이다. 장비, 레벨, 능력치가 바뀔 때마다 `compute_thaco`/`compute_ac`를 다시 실행한다.

즉 몬스터 스탯은 "읽고", 플레이어 스탯은 "계산한다". 저장 모델에서 몬스터 전투 스탯은 불변 템플릿으로, 플레이어 전투 스탯은 파생 캐시로 설계한다.

**공식은 상수 테이블로 외부화한다.** 원본은 `global.c`에 하드코딩돼 있다. 다음 값을 모두 데이터로 분리해 **코드를 고치지 않고 밸런스를 튜닝할 수 있게** 한다.
- `bonus[64]`·`thaco_list[13][20]`·`prof_array[클래스][12]`
- 주사위 파라미터
- 특수공격 확률(13%/10%/15%…)
- 사망 손실률(5%/6.7%/10만)

이는 이슈 목표인 "밸런스 유지"와 바로 연결된다.

**결정 필요(#14)**:
- ① 전투 모델을 몬스터 기반(원본 충실)으로 할지, 플레이어 독립 공격 루프를 추가할지. 현재 판단은 몬스터 기반 재현이다.
- ② `cp` 미초기화 그룹킬 보너스의 원래 의도. 파티/그룹이 데미지에 기여했을 때 `+exp/10`을 결정적으로 적용할지(권장), 폐기할지.
- ③ `PHASTE` 가속 무효, `PBLESS` thaco 미반영 같은 버그성 dead 코드를 의도대로 살릴지(가속이 실제로 공격 속도를 올리게), 원본대로 무효로 둘지.
- ④ 하드코딩된 사망 부활 방 `1008`을 설정값이나 종족별 부활지로 확장할지.
