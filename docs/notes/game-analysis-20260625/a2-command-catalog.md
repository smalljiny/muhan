# A2 명령 체계 카탈로그

> 무한의 전 플레이어 명령을 oracle에서 추출해 카탈로그화한다. 명령 파서 설계·구조화 이벤트 프로토콜 범위의 입력. 이슈 #2. 출처는 `legacy/muhan/src`(EUC-KR).

## 개요

무한의 명령 체계는 **단일 중앙 디스패치 테이블 `cmdlist[]`**(`global.c`)로 구동된다. 테이블은 **350개 엔트리**(한글 명령어·별칭) → **174개 고유 핸들러 함수**로 매핑된다(카탈로그는 176행 = 174 핸들러 + `special_cmd` 분기 + 그룹 표기 차이; `move`·`action`이 84개 별칭을 2행으로 흡수). 입력 한 줄은 `parse()`로 토큰화되고 `process_cmd()`가 테이블을 선형 탐색해 핸들러를 호출한다. 핵심 특징은 **한국어 동사-후치(verb-final) 파싱** — 입력의 *마지막 토큰*을 명령 동사로 취한다 — 과 **약어(부분 일치) 매칭**, **사용자 별칭**, **`*` 접두 관리자 명령**이다.

명령군 분포(174 고유 핸들러, 카탈로그 176행):

| 명령군 | 카탈로그 행 | 대표 명령 |
|---|---|---|
| 관리(DM) | 52 | `*순간이동` `*괴물` `*시켜` `*종료` |
| 소셜 | 33 | `말` `감정표현`(40 이모트) `패거리말` `결혼` |
| 정보 | 30 | `봐` `도움말` `누구` `건강` `소지품` |
| 아이템 | 29 | `주워` `입어` `사` `팔아` `제련` `은행` |
| 전투 | 12 | `공격` `기습` `맹공` `차기` `기공집결` |
| 이동 | 11 | `move`(방향 44별칭) `가` `열어` `따` `귀환` |
| 마법 | 9 | `주문` `배워` `읽어` `방혼술` `참선` |

> 카탈로그 행 합계 176(174 고유 핸들러 + `special_cmd` 분기 + 그룹 표기). 직업 한정 버프 스킬(`기공집결`·`신원법` 등)은 직업 효과 성격상 전투/마법으로 분산 분류했다. 권한 컬럼은 표본 4셀(`dm_purge`·`dm_force`=SUB_DM↑, `기습`=THIEF/ASSASSIN, `사`=RSHOPP)을 oracle 본문과 대조 검증했다.

> **데이터 압축 주의(페이징 규모 입력)**: 176 핸들러 ≠ 176 구현 단위다. `move`(이동) 단일 핸들러가 44개 방향 별칭(한글/jamo/numpad/방 출구명)을, `action`(감정표현) 단일 핸들러가 40개 이모트 별칭을 데이터 구동으로 흡수한다. 350 엔트리 중 다수가 **얇은 별칭**이다. 또한 52개 관리(DM) 명령은 게임플레이가 아니라 운영 도구로 분리 가능하다. 실질 게임플레이 명령 구현 표면은 **약 124 핸들러**(176−52), 그중 다수가 공통 패턴(대상 해석 + 방 플래그 게이트 + 쿨다운)을 공유한다.

## 디스패치 아키텍처

입력 → 출력 경로는 `command1.c`에 집중돼 있다.

```
io->fn = command (io.c handle_commands가 회전당 1줄 디스패치 — A1 참조)
   │
   ▼
command(fd, param, str)          command1.c:415
   │  · "!" / "!xxx" → 직전 명령 히스토리 치환
   │  · lowercize(str)           (영문만 소문자화; 한글 무영향)
   │  · cmnd.fullstr = str       (원문 보존 — say/외쳐 등이 사용)
   ▼
parse(str, &cmnd)                command1.c:505   ← 한국어 동사-후치 토큰화
   ▼
alias_cmd(ply, &cmnd)            (사용자 별칭 매칭; 4000 반환 시 통과)
   ▼
process_cmd(fd, &cmnd)           command1.c:560   ← cmdlist 선형 탐색·디스패치
   │  · cmdno < 0  → special_cmd(ply, -cmdno, cmnd)
   │  · cmdfn 호출  → (*cmdlist[c].cmdfn)(ply, cmnd)
```

### 한국어 동사-후치 파싱 (핵심 발견)

`parse()`(`command1.c:505`)는 일반 MUD 파서와 다르다. 한국어는 **동사가 문장 끝에 오는 SOV** 언어이므로, 명령 동사(=핸들러 키)를 **마지막 토큰에서** 뽑는다:

```c
/* 입력이 공백/./!/? 로 끝나면 → 명령을 "말"(say)로 기본 처리 */
if(str[j-1]==' ' || str[j-1]=='.' || str[j-1]=='!' || str[j-1]=='?') {
    strncpy(cmnd->str[n++], "말", 20);   /* 문장 종결부호 = 발화 단축 */
}
else {  /* 마지막 공백 뒤 토큰을 명령 동사 str[0]로 */
    i=j; while(i>=0 && str[i]!=' ') i--;
    strncpy(cmnd->str[n++], &str[i], 20);
}
/* 나머지 앞쪽 토큰들은 인자(str[1..], val[1..])로 순차 파싱 */
```

→ `용을 칼로 공격` 에서 마지막 토큰 `공격`이 명령, `용`·`칼로`가 인자다. 마침표/물음표/느낌표로 끝나면 문장 전체를 `말`(say)로 간주해 **자연스러운 채팅**을 만든다(`안녕하세요.` → 발화). 이는 telnet 자유 텍스트 입력에 한국어 어순을 입힌 **콘텐츠 수준의 설계 결정**이다.

- 토큰은 `cmnd->str[i]`(단어, 최대 20자)와 `cmnd->val[i]`(숫자)로 분리된다. `is_number` 토큰은 `val[]`로, 나머지는 `str[]`로. 다수 핸들러가 `cmnd->val[1]`을 **N번째 동명 객체** 서수로 사용한다(예 `칼 2` = 두 번째 칼).
- 관사/불용어 제거 로직은 원본에서 주석 처리돼 비활성(영어 잔재).

### 명령 매칭 (`process_cmd` + `str_compare`)

`process_cmd()`(`command1.c:560`)는 `cmdlist[]`를 **선형 탐색**한다:

```c
do {
    if(!strcmp(cmnd->str[0], cmdlist[c].cmdstr)) { match=1; cmdno=c; break; }  /* 정확 일치 우선 */
    else if((current_deep = str_compare(...)) != 0) {       /* 약어(부분) 매칭 */
        if(match_deep==0 || match_deep > current_deep) { cmdno=c; match_deep=current_deep; }
    }
    c++;
} while(cmdlist[c].cmdno);   /* cmdno==0 (@ 엔트리) = 종료 sentinel */
```

- **정확 일치**가 최우선, 없으면 `str_compare`의 "deepness"가 **가장 작은**(=가장 근접한) 약어 후보를 선택한다. 즉 `공`만 쳐도 `공격`에 매칭될 수 있다(테이블에 짧은 별칭 `공`도 별도 존재).
- 테이블은 `{ "@", 0, 0 }`로 종료된다(cmdno 0 sentinel).

### 특수 명령 (`special_cmd`)

cmdno가 **음수**인 엔트리는 핸들러 대신 `special_cmd(ply, -cmdno, cmnd)`로 분기한다. 현 테이블의 유일 사례:

| 명령 | cmdno | 분기 | 효과 |
|---|---|---|---|
| `눌러` `밀어` | -2 | `special_cmd(ply, 2, …)` | 특수 오브젝트 상호작용. `special1.c:91` switch(SP_*)가 맵스크롤·콤보·특수 오브젝트를 처리. |

### 사용자 별칭 (`alias_cmd`)

`process_cmd` 이전에 `alias_cmd`가 플레이어 정의 별칭을 먼저 검사한다. 별칭은 `줄임말`(`ply_aliases`) 명령으로 등록하며(최대 14자), 등록된 별칭 입력 시 확장 명령으로 치환돼 `alias_buf` 큐를 통해 재처리된다(`io.c` handle_commands가 alias 큐를 우선 소비, A1 참조).

### 명령 히스토리

`!` = 직전 명령 반복, `!xxx` = 직전 명령 + `xxx` 접미. `lastcommand`(79자)에 보관.

## 권한 모델

권한은 `creature.class` 정수(0~12)로 표현된다(`mtype.h:93~`):

| 클래스값 | 상수 | 구분 |
|---|---|---|
| 0 | ZONEMAKER | 빌더(특수). 전투 금지 |
| 1–8 | ASSASSIN·BARBARIAN·CLERIC·FIGHTER·MAGE·PALADIN·RANGER·THIEF | 일반 플레이어 직업 |
| 9 | INVINCIBLE | 무적(고레벨/준관리) |
| 10 | CARETAKER | 초인(관리자 하위) |
| 11 | SUB_DM | 부 관리자 |
| 12 | DM | 관리자 |

권한 게이트는 두 층이다:

1. **`*` 접두 게이트**(전역, `process_cmd`): `cmnd->str[0][0]=='*'` 이고 `class < CARETAKER(10) && class != ZONEMAKER(0)` 이면 "이런 명령어는 없네요"로 차단. 즉 모든 `*` 명령(관리)은 CARETAKER↑ 또는 ZONEMAKER 필요. DM 명령은 `log_dmcmd`로 별도 감사 로깅된다.
2. **핸들러 내 게이트**(개별): 직업 한정 스킬은 `class == X` 정확 비교 + `INVINCIBLE(9)↑` 우회를 본문에서 검사한다(예 `기습`=THIEF/ASSASSIN, `차기`=BARBARIAN, `신원법`=CLERIC/PALADIN). DM 명령도 내부에서 SUB_DM↑ vs DM↑로 세분된다(읽기성 명령은 SUB_DM, 파괴·영속성 명령은 DM). 추가로 레벨(`broadsend`=20↑), 나이(`vote`=21↑), 방 플래그(상점·은행·수련장 등), 플레이어 플래그(`PFMBOS` 가문 두목 등)로 게이트한다.

## 아키텍처 함의 (이슈 #14·파서 설계 입력)

**핵심 판단: 자유 텍스트 파서 자체가 형상이다. 명령 *어휘·의미*만 콘텐츠로 남는다.** A1이 런타임 루프를 "삭제하고 플랫폼 채택"으로 결론낸 것과 평행하다 — 무한의 `parse()`+`cmdlist[]` 선형 탐색은 telnet 한 줄 텍스트라는 입력 채널의 제약에 대한 해법이었다. 구조화 WebSocket+JSON UI에서는 클라이언트가 명령과 인자를 **이미 분리해** 전송하므로, 동사-후치 토큰화·약어 매칭·관사 제거는 대응물이 없다.

분리 원칙: **파싱/디스패치 메커니즘은 형상, 그 위에 실린 명령 집합·인자 의미·권한은 콘텐츠.** 다음이 설계 결론이다.

- **명령 = 구조화 이벤트.** 클라이언트는 `{ cmd: "attack", target: "용", ordinal: 1 }` 형태로 보낸다. 서버는 `cmd` → 핸들러 레지스트리(map) 1:1 매핑. 350-엔트리 선형 탐색·`str_compare` deepness는 불요. 한글 명령어는 **클라이언트 표시 레이블·입력 별칭**으로 유지(어휘는 콘텐츠).
- **동사-후치는 UI 레이어로 흡수.** 문장 종결부호=발화(say) 단축, 대상이 동사 앞 어순은 telnet 자유 입력에서만 의미가 있다. 자유 채팅 입력란(say/이모트)과 구조화 명령(버튼·메뉴·타겟 선택)을 분리하면 자연스럽게 재현된다. **단, 자유 텍스트 입력 모드를 옵션으로 제공한다면** 동사-후치 파싱은 한국어 사용자 경험의 콘텐츠이므로 그 모드 한정으로 이식한다.
- **프로토콜 커버 범위**: 구조화해야 할 명령은 게임플레이 약 124개. 이 중 인자 형태는 소수 패턴으로 수렴한다 — (a) 무인자(소지품·건강·저장), (b) 대상 1개+서수(공격·감정·get), (c) 대상+보조 대상(훔쳐·줘·교환), (d) 자유 텍스트(say·외쳐·이모트), (e) 대화형 다단(제련·편지·결혼). 프로토콜은 이 5개 인자 형태를 커버하면 충분하다.
- **페이징 규모**: 구현은 명령군 단위로 페이징한다 — 이동·정보(얇음, 우선) → 아이템·경제 → 전투·마법(A5/마법 분석 의존) → 소셜·패거리·결혼 → 관리(DM, 별도 권한 레이어). `move`(44 별칭)·`action`(40 이모트)은 **데이터 테이블 1개씩**으로, DM 47개는 운영 콘솔로 묶어 게임플레이 페이징에서 분리한다.
- **권한은 별도 레이어.** `*` 접두 + 클래스 게이트는 입력 파싱이 아니라 **명령별 권한 정책**(미들웨어)으로 분리한다. 직업 한정 스킬(`기습`=THIEF 등)도 동일 레이어에서 선언적으로 게이트.
- **사용자 별칭(`줄임말`)은 콘텐츠.** 플레이어가 자기 매크로를 만드는 기능은 게임 기능이다. 클라이언트 매크로 또는 서버 측 별칭 테이블로 재현한다(파싱 메커니즘 `alias_buf`는 형상).

- 경제 명령(`사`·`팔아`·`수리`·`향상`·은행)의 가격·비용 산출식, `train`/`change_class` 경험치 비용 → **경제 분석**.
- 방 플래그(RSHOPP·RBANK·RTRAIN·RPOSTO·RFORGE·RMARRI 등) 전체 의미 → **방 데이터 분석**.
- 직업 한정 스킬의 쿨다운(LT_*) 슬롯별 interval 값 → A1 lasttime 모델과 연계.
