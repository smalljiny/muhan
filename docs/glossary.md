# 용어 기준

> 문서, 코드 주석, 테스트 제목을 쓸 때 따르는 한국어 용어 기준이다. 같은 대상은 한 이름으로 부르고, 영어를 한자어로 직역한 조어는 쓰지 않는다.

## 원칙

- 같은 대상은 문서 전체에서 한 이름으로 부른다.
- 영어 개념을 한자로 그대로 옮긴 조어(형상, 정본, 배선 등)를 만들지 않는다. 쉬운 일반어로 쓰고, 마땅한 말이 없으면 영어 용어를 그대로 쓴다.
- 코드 식별자, 경로, 파일 이름은 이 기준과 관계없이 코드에 있는 그대로 쓴다.
- 원작 무한대전의 게임 용어(패거리, 두목, 냥, 전당포, 명령어 이름)는 원작 그대로 쓴다.
- 새 문서나 주석이 이 표에 없는 용어를 자주 쓰게 되면 이 문서에 추가한다.

## 포팅 원칙 용어

| 용어 | 뜻 |
|---|---|
| 콘텐츠 | 게임이 *무엇을* 하는가. 규칙, 공식, 수치, 데이터. 충실히 이식한다 |
| 구현 방식 | 원작 코드가 그것을 *어떻게* 구현했는가. 1993년 기술 제약에서 나온 구현 수단과 세부 사항이며 버그와 죽은 코드도 포함한다. 재현하지 않고 다시 설계한다 |
| 이식 / 재설계 | 분류 표에서 쓰는 행동 꼬리표. "이식(공식) / 재설계(트리거)"처럼 쓴다 |
| 오라클 | 동작 명세로 삼는 원본 C 코드(`legacy/muhan/src`). 이식 대상이 아니라 동작을 대조하는 기준이다 |
| as-shipped | 원작이 실제로 출시된 동작을 그대로 재현하는 정책 |
| 구현 방식 개선 | as-shipped와 짝을 이루는 정책. 원작의 구현 방식은 새 스택으로 개선한다 |
| as-compiled / as-intended | 실제로 컴파일된 동작과 원작자가 의도한 동작. 두 동작이 다를 때 대비하는 말이다(A10 CHECKFAMILY 논의) |
| as-built | 지금 포트에 구현된 동작 |
| 원작과의 차이 (divergence) | 포트가 오라클과 다르게 동작하는 곳. 이미 확인해 기록한 것은 "알려진 차이"라고 한다 |

## 게임 대상의 이름

| 대상 | 문장에서 쓰는 말 | 코드·경로에서만 쓰는 말 | 쓰지 않는 말 |
|---|---|---|---|
| 플레이어가 아닌 생물 | 몬스터 | `creature`. 코드 타입(`CreatureInstance` 등)을 가리킬 때만 '크리처' | 몹, 괴물 (원작 명령어 `*괴물` 인용은 예외) |
| 줍고 착용하는 물체 | 아이템 | `object`(원본 구조체, DB 컬렉션, 코드 이름) | 오브젝트, 물건 |
| 게임 속 인물, 저장 데이터 | 캐릭터 | `character` | — |
| 캐릭터를 조종하는 쪽, 전투에서 몬스터와 대비되는 쪽 | 플레이어 | `player` | 유저 |
| 로그인 단위 | 계정 | `account` | — |
| 웹 UI를 쓰는 사람 | 사용자 | — | — |
| 이동할 때 순서대로 거치는 거부 검사 목록 | 게이트 검사 | `evaluateMoveGates`, `MOVE_GATE_ORDER` | 건틀릿 |

## 서버 상태 용어

| 용어 | 뜻 |
|---|---|
| 라이브 | 프로세스 메모리에 있는 현재 게임 상태와 그 레지스트리(라이브 상태, 라이브 레지스트리). 프로젝트 용어로 유지한다 |
| 기준 상태 (authoritative) | 진실의 원천으로 삼는 상태. 이 프로젝트에서는 인메모리 라이브 상태가 기준이고 DB는 세이브 계층이다. 처음 나올 때만 "기준 상태(authoritative)"로 쓰고, '권위 상태'라고 쓰지 않는다 |
| 확장 지점 (seam) | 의존성을 바꿔 끼우는 지점. 문서마다 처음 나올 때만 "확장 지점(seam)"으로 쓰고 이후에는 seam이라고 쓴다. 코드 주석에서는 seam만 쓴다 |

## 바꿔 쓰는 말

번역투 조어와 그 대체어다. 왼쪽 말은 쓰지 않는다.

| 쓰지 않는 말 | 쓰는 말 | 예외 |
|---|---|---|
| 형상 | 구현 방식 / 구조 / 형태 / 패턴 (뜻에 따라) | — |
| 정본 | 기준(기준 문서, SSOT) / 원본, 빌드본(실제 빌드되는 파일) | — |
| 배선, 결선 / 미배선 | 연결 / 미연결. 의존성 조립을 잘못한 프로그래밍 오류는 "조립 오류" | — |
| 해소, 해소자 (resolve) | 해석, 리졸버 | 문제·충돌·blocking 해소 |
| 소유한다 (책임) | 담당한다 | 데이터·객체 소유권(`object.owner`, 소유자) |
| 발화 (fire) / 미발화 | 실행, 발생 / 실행되지 않음 | 게임의 말하기(발화 차단, 발화자) |
| 소관 | 담당 | — |
| 유예 | 보류, 후속으로 미룸 | grace period는 "여유" |
| 부재 | 없음, 빠져 있음 | — |
| 수렴 (종료·정리) | 정리, 일괄 종료 | 여럿이 하나로 모인다는 뜻 |
| 구동 (-driven) | ~ 기반 | — |
| 표면 (API·명령 표면) | 범위, 접점, 인터페이스 | 공격 표면, 인젝션 표면 |
| 정합 (단독) | 일치 | 정합성 |
| 투영 | 변환 | — |
| 폐형 | 닫힌 식 | — |
| 승격 | 올림, 별도 필드로 만듦 | 역할 승격(권한 상승) |
| 전사 (transcribe) | 옮겨 적기 | 직업 전사 |
| 판독 | 읽기 | — |
| 물질화 | 인스턴스 생성 | — |
| 랜딩, 착지 | 머지, 반영 | — |
| 함의 | 시사점. 논리적 함의는 "포함" | — |
| 1급 | 독립, 핵심 | — |
| 이월 / 반려 / 규명 | 넘김 / 기각 / 정리, 분석 | — |
| 값역 / 적재 / 기동 | 값 범위 / 로드(무게 소지는 "소지") / 시작 | — |
| 무성 / 재용도 | 조용한, 알림 없는 / 다른 용도로 재사용 | — |
| 상정 / 취득 | 가정 / 가져오기 | — |

## 뜻이 틀리기 쉬운 말

| 쓰지 않는 말 | 쓰는 말 | 이유 |
|---|---|---|
| 승계된 소켓 | 밀려난 소켓 | 재로그인으로 교체된 옛 소켓이다. '물려받은'으로 읽힌다 |
| 정렬 (alignment) | 성향 | 정렬(sorting)과 부딪힌다 |
| 발산 (오라클과의 차이) | 어긋남, 차이 | 수학의 '무한대로 감'으로 읽힌다. 값이 상한 없이 커지는 뜻이면 유지 |
| 결정적 (decisive) | 핵심, 중요한 | 결정론적(deterministic) 뜻의 '결정적'은 표준어라 유지 |
| 절삭 | 버림 | 소수점 처리는 버림이다 |
| 권위적으로 | 최종 기준으로 | 한국어로는 '고압적'이라는 뜻이다 |
| 치명 이벤트 | 중요 이벤트 | 게임 문서에서 사망 이벤트로 읽힌다 |
| 반대급부 | 대가, 단점 | 반대급부는 '대가로 얻는 이익'이다 |
| 대우 (논리) | 부정 | 대우(contrapositive)와 부정을 구분한다 |

## 영어 그대로 쓰는 말

dirty, hydrate, write-behind, flush, seam, FSM, LWW, SSOT, fixture, property 테스트, 포트, 어댑터, 리졸버, 에픽, 토픽, Story는 영어 또는 개발 표준어 그대로 쓴다. '더티', '하이드레이트'처럼 소리만 옮기지 않는다.

## 문장 쓰기

- 가운뎃점(·)으로 명사를 4개 이상 잇지 않는다. 목록이나 문장으로 푼다.
- 한 문장에 대시(—)를 두 번 넘게 쓰지 않는다. 뒷부분이 이유이면 "~때문이다"로 바꾼다.
- 굵은 글씨는 문단마다 핵심 한 곳에만 쓴다. 목록 머리말은 예외다.
- "~위에 선다", "얹다", "접힌", "전진한다", "척추" 같은 은유 대신 뜻을 그대로 쓴다.
- 기술 문서는 "~다" 평서형으로 쓴다.
